# v0.15.0

**The phone never operates WeChat — one tap locks you out of your own WeChat.**

Measured: reading WeChat is fine. **The very first accessibility-injected tap** makes WeChat protect its own
window — **screenshots go black for you too, not just for Andee** — and it stays that way across a
force-stop. Only clearing WeChat's data and logging in again clears it. So the phone refuses the gesture
before sending it.

Also in this release: **a quit that needs no balance** and a **switch that actually frees the microphone** —
both from issues you filed — plus a context that is **pruned, archived and readable** instead of dropped.

> **These binaries carry no credentials.** No CodeFlying key, no voice-provider key, and no Google key.
> **You supply your own**: sign up from the link inside the app, then paste the key into
> **Settings → Backend**. Starting is free and the free allowance is finite.
>
> Each package already points at the right server for its language — the English ones at
> `myapp.codeflying.app`, the Chinese at `baas.kuafuai.net`. You do not choose this.
>
> **The macOS packages are signed with a local identity, not an Apple Developer ID**, so Gatekeeper
> refuses the first launch. On macOS 15 the old "right-click → Open" trick no longer exists; see
> **[Opening the Mac app](#opening-the-mac-app)**.

## Highlights

- 🔴 **The phone will not tap WeChat, and that is a protection rather than a limit.** One automated tap puts
  WeChat into a state where **you cannot screenshot it either**, and a force-stop does not clear it. Reading
  WeChat still works.
- **You can quit without a balance.** The control bar's ✕ was minimise, and typing 退出 went to the model —
  so a user out of balance **could not quit**. There is now a power key that runs locally.
- **A mic switch that keeps your enrolment.** Wake listening held the microphone 24/7 for people who only
  type, and 清除 was the only off-switch — and it discarded the phrase.
- **A restart no longer loses the thread**, and **what leaves the context can be read back.**

## What's Changed

### Added

- **A quit entry that runs locally — no model, no balance.** Reported in
  [#44](https://github.com/kuafuai/andee/issues/44): *「我就在里面打个退出，它都说余额不足，还要调用大模型，这设计
  不合理呀！」* The control bar had no real quit — the ✕ was **minimise** — and the only ways out were
  speaking 「退出安迪」 or typing it, where **typing was a model turn**. A **power key left of 收起** now
  pops a confirm and runs the same local teardown the spoken phrase runs: **no model, no voice, no balance**.
  - **Typing 退出 Andee exits too**, on the explicit phrasing only — a bare 退出 stays an ordinary turn, as
    does 「怎么退出」.
  - 朋友 moved into Settings to make room.
- **A switch that actually frees the microphone.** Reported in
  [#45](https://github.com/kuafuai/andee/issues/45): *「它的那个送话器的图标一直在手机上 24 小时不间断的监听着
  语音呢，其实我也没有开通语音。都是打字在弄，很耗电。」* Wake listening **held the mic 24/7** even for users
  who only type — the status-bar mic dot never went away — and **the only off-switch was 清除, which threw
  the enrolment away**. There is now **`VoiceConfig.wake_on`**, **read live by the wake gate**, and **a mic
  key beside the ball's speaker** that toggles it **while keeping the templates**. The key appears **only
  when a phrase is enrolled**, so it is not clutter for people who never set one up.
- **A restarted brain picks the conversation up again.** A harvest used to leave nothing behind but a
  summary, so **an update, a crash, a kill or a backend change dropped the thread**. The brain now starts
  from **the last summary plus the scrollback rows since it**, **at most 24 hours** old.
- **An archive of what the context dropped.** Whatever a harvest or a trim removes is **written down
  first** — the words, the tool calls, results up to **3 000 characters** — and **`read_earlier` reads it
  back**. Trims in a row share one archive, and at most **100** are kept. It never holds the vault, SMS,
  contacts or notifications.

### Changed

- 🔴 **The phone refuses to operate WeChat.** The measurement, on a HONOR phone with **WeChat 8.0.80**:
  installing Andee, enabling accessibility, **reading the screen and screenshotting it were all fine**. The
  **very first accessibility-injected tap (09:56:39)** was followed five seconds later by the window
  carrying **`FLAG_SECURE`** and its accessibility tree coming back **empty** — and it **stayed that way
  across a force-stop**. Only clearing WeChat's data and logging in again recovered it.

  > So a single tap does not just fail. **It locks the user out of screenshotting their own WeChat.**

  WeChat detects the injected gesture — a `dispatchGesture` event is flagged as coming from an
  accessibility service. The phone's dispatcher therefore **refuses the write methods** when WeChat is in
  front, **before the gesture is sent**: `screen.tap`, `screen.tap_id`, `screen.tap_target`,
  `screen.long_press`, `screen.long_press_id`, `screen.swipe`, `screen.type`, `screen.submit_input`.
  - **Reads and global navigation stay open** — `screenshot`, `ui_tree`, `look_region`, `wait`, and system
    back/home, which lets Andee **leave** WeChat. None of them triggered the state, and a body that cannot
    even read WeChat is **worse and no safer**.
  - The refusal **names WeChat as the cause** and points the model at **the desktop Andee and
    `ask_friend`** — so this degrades into a different route rather than a dead end.
  - **Phone-only.** macOS WeChat was verified fine, so the guard lives in the **Android dispatcher**, not
    in `core`.

- **The context is pruned before it is harvested.** Measured on the Mac's log: **every** harvest fired on
  the character budget **and the tail it kept was still over it**. The weight was **old tool results** and
  **the index block every user message carries** — and the budget **counted the ~50 000-character system
  prompt**, leaving **~10 000 for the conversation**. Now `ContextPruner` turns old tool results into a
  one-line stub and strips old messages' index blocks **before** a harvest (**no model call, the words
  untouched**), and the budget counts **the conversation only — 40 000 characters**.
- **A harvest the user talks over is retried**, and **a background turn no longer abandons a user sentence
  queued in the same instant**.
- **`TopicSplitter` knows every index section**, so a folded topic stops carrying them.
- **The harvest summary has four parts**, carried from one harvest to the next.

## Known issues

- **The WeChat guard is a refusal, not a detection of what WeChat did.** It is keyed to the foreground
  package being `com.tencent.mm`. A WeChat version that behaves differently, or a build that fronts WeChat
  under another package, would not be covered — and **the guard has been exercised on one phone with one
  WeChat version (8.0.80)**.
- **Nothing here recovers a WeChat that is already in that state.** If it has happened, the only fix found
  is clearing WeChat's data and logging in again — which loses the local chat history.
- **The new quit path is a local teardown, so it does not ask the model to say goodbye.** Anything a turn
  would have done on the way out does not happen. That is the point of the change, and it is still a
  behaviour difference from the spoken phrase.
- **`wake_on` defaults to on**, so an existing install keeps listening until the switch is used. Users who
  want the mic free must turn it off once — that is a deliberate default, not an oversight.
- **The context archive is not encrypted differently from the rest of the notebook** and it **grows** —
  100 archives of up to 3 000 characters per tool result. Nothing prunes it by age or size yet beyond the
  count.
- **The pruning behaves as measured on the Mac's log**, which is where the numbers came from. The phone's
  context is shorter, so how much the pruner and the 40 000-character budget matter there has not been
  measured.
- **The task lifecycle has not been run end to end with a real model** (v0.14.0), **merge-undo has not been
  exercised over its 30 days**, and **Android 8.1–10 still cannot see the screen** (v0.13.0) — that path
  still has not been run on a real 8.1–10 device.
- **The Mac screenshot fix (v0.14.2) still has not been run on the machine that had the problem** — a
  3024×1964 XDR MacBook. What was verified is that the code is the API that worked before the regression
  and that it is really in the package.
- **Neither pet has been lived with for a day**, and the pet's picture library is Mac-only (v0.12).
- **The ball's face has never been verified on real hardware here.** Carried from v0.8.1: the eyes are 3D
  capsules under perspective projection, so a flat rendering cannot stand in for the real thing.
- **What it keeps for itself is per device.** The one on your phone and the one on your Mac each have their
  own record. They do not share a notebook. This is deliberate rather than pending.
- **Nothing verifies that a key is accepted by the server it is sent to.** These packages are checked for
  the right server and the absence of credentials; whether a given CodeFlying key works against
  `baas.kuafuai.net` versus `myapp.codeflying.app` has not been exercised end-to-end.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships with a single newline,
  which reads as empty. A key written into it would outrank every build setting.
- Two issues from `v0.1.0` are **unchanged and untouched**: `tools/verify_faces_lab.py` still reports
  7/16 assertions passing, and the debug WebSocket server (`net/BodyWsServer`) still binds `0.0.0.0:9008`
  with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. On Android the app asks for accessibility,
overlay, notification access, SMS and call log, and it can complete a payment by tapping; on the Mac it
asks for accessibility, screen recording and notifications. The only guardrail on that path is Android's
`FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the model, not enforcement.

**One permission did get narrower, and it is worth being precise about.** The phone now declines to send
taps, swipes and typing into WeChat. It still **reads** WeChat, and it still operates every other app —
including apps that hold more of your money than WeChat does. This is a **refusal in the dispatcher**, not
a sandbox: it stops the one gesture that was measured to break your WeChat, and it does not claim to be a
general limit on what the accessibility service can do.

### Opening the Mac app

The `.dmg`s are signed with a local identity, not an Apple Developer ID, so Gatekeeper refuses the first
launch of a downloaded copy.

⚠️ **On macOS 15 (Sequoia) and later, "right-click → Open" no longer works** — Apple removed that
override, and most advice online still recommends it. The current route:

1. Double-click the app. It will be refused. Dismiss the dialog.
2. Open **System Settings → Privacy & Security** and scroll to **Security**.
3. There is a line naming Andee as blocked, with an **Open Anyway** button beside it.
4. Confirm, and authenticate.

That button **only appears for about an hour** after the failed launch. If it is missing, launch the app
again and go straight back to Settings.

One more thing worth knowing: the app **inside** the mounted dmg carries no quarantine flag, so it may
launch straight from the dmg — and then be blocked once you drag it to Applications, which does attach
one. Both behaviours are normal; neither means a damaged download.

### What you supply

No package has a key. After installing, open **Settings → Backend** and either paste a CodeFlying key
(sign up from the link in that panel) or switch to **on-device** and give it an OpenAI-compatible
endpoint and model.

**For voice, a key alone may not be enough.** If you use Volcengine, the service must be an *entitled*
resource, not just an opened one — see
[docs/getting-started.md](../getting-started.md). Android can also use the system voice instead, and
without any voice it is silent but still works on screen.

> **Would you rather not configure keys at all?** Use the one-click page instead —
> **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you want,
> tap the build button, and you get a package with the **tokens already configured** plus a QR code to
> scan. Starting is free and the free token allowance is **finite — once it runs out, tokens must be
> bought.** It is a separate service with no direct relationship to this project, with its own terms,
> pricing and data handling. Note it produces **an Android APK, not a Mac app** — macOS packages can
> only be built on macOS.

## Install from source

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.15.0

# one variant, by hand:
./gradlew :app:assembleDebug -PdefaultLang=en -PcodeflyingDomain=myapp.codeflying.app -PcodeflyingSsl=true

# or all ten files, the way the release was built:
bash ~/.workbuddy/skills/andee-release-ship/scripts/build_variants.sh
```

`-PcodeflyingKey=` and `-PgoogleVoiceKey=` are refused on purpose — a published package carries no
credential.

There is a getting-started guide: **[docs/getting-started.md](../getting-started.md)**, and
**[docs/getting-started.zh-CN.md](../getting-started.zh-CN.md)** in Chinese.

**Upgrading:** `versionCode` moves `29 → 30`, so the Android package installs over v0.14.2 normally. The
Mac app's version string follows the same number. Existing memory, notebook, todos and chat history are
untouched, **and your wake phrase enrolment is kept** — the new mic switch turns listening off without
discarding it. **One behaviour changes on the phone:** Andee will no longer tap, swipe or type inside
WeChat, because doing so was measured to break your WeChat. It still reads WeChat.

**Full Changelog**: https://github.com/kuafuai/andee/compare/v0.14.2...v0.15.0
