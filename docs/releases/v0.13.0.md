# v0.13.0

**Installs on Android 8.1 now — with an honest warning about what is missing — and you can set how
strictly the wake phrase has to match.**

`minSdk` moves 30 → 27. The screen tools are built on an API 30 screenshot call, so on 8.1–10 the app
installs, talks and runs **but has no pixels to aim with**. Rather than let the installer reject the whole
package, it says so at the top of the checklist.

> **These binaries carry no credentials.** No CodeFlying key, no voice-provider key, and no Google key.
> **You supply your own**: sign up from the link inside the app, then paste the key into
> **Settings → Backend**. Starting is free and the free allowance is finite.
>
> Each package already points at the right server for its language — the English ones at
> `myapp.codeflying.app`, the Chinese at `baas.kuafuai.net`. You do not choose this.
>
> **The macOS packages are signed with a local identity, not an Apple Developer ID**, so Gatekeeper
> refuses the first launch. On macOS 15 the old "right-click → Open" trick no longer exists; see
> **[Opening the Mac app](#opening-the-mac-app)**.

## Highlights

- **It installs on an older phone now.** `minSdk` 30 → 27, so Android 8.1 and up take the package instead
  of having the installer refuse it.
- **…but on 8.1–10 it cannot see the screen.** That is not a bug and it is not hidden: the app names the
  lost features at the top of its own checklist and in the startup nudge, and says what still works.
- **唤醒词 严格 / 标准 / 灵敏 / 很灵敏.** If it keeps missing your wake phrase, or keeps waking on the TV,
  there is now a dial — and the picker tells you where the safe range ends.
- **Two fixes for Android 11 and for the older devices this release adds** — reminders were silently
  inexact on 11, and the window insets counted the status bar twice on pre-30.

## What's Changed

### Added

- **唤醒词严格度, in Settings → 唤醒词**: 严格 / 标准 / 灵敏 / 很灵敏. It **scales the threshold learned at
  enrolment** (×0.85 / ×1.0 / ×1.2 / ×1.4) **rather than replacing it** — so it survives a re-enrolment,
  and 标准 is exactly the behaviour every device had before this existed. Written on tap and read on every
  segment, so a change is live on the next thing you say.
  - **The picker says where the safety runs out.** 灵敏 at the learned cap reaches 2.16, still **short of
    every impostor measured** (2.21–2.59). **很灵敏 reaches into them** — the note says so in as many
    words — and the result is capped at 2.4. An unreadable value falls back to **严格**, the deaf
    direction, leftmost in the list.
- **The app installs on Android 8.1–10 (API 27+) instead of refusing.** Chat, voice, the notebook and
  settings all work. What is gone is named in an **amber row at the top of the self-check** and in the
  startup nudge:

  > 当前是 Android %1$s（API %2$d），低于 Android 11。屏幕截图、看图点击、窗口毛玻璃等依赖新系统接口的
  > 功能不可用；聊天、语音、笔记和设置仍可正常使用。升级到 Android 11 及以上即可恢复。

  So: **screen capture, visual tap targeting and window blur** need newer system APIs. **Upgrading to
  Android 11 or later restores them** — nothing else about the app is different.

### Fixed

- **The status bar was counted twice** in the pre-30 window insets — on exactly the devices this release
  adds. `legacyInsets` read the height difference between `real` and `app` as the navigation bar, but that
  difference **already excludes the status bar too**, so adding `status_bar_height` on top described
  **three bars' worth of inset on a device with two**. The cost landed where you would notice it: the
  folded ball rested a status bar **above** the navigation bar, and every card came back a status bar
  **shorter** than the screen it is centred on. Portrait and landscape fail differently (at the bottom the
  bar is empty width and shows up in the height difference; on a side it is the other way round), so the
  status bar now comes out of whichever axis holds the navigation bar. Which side that is remains a stated
  assumption — read from the width difference, which is where the measured ROMs put it in landscape —
  rather than an unstated one.
- **Reminders were silently inexact on Android 11.** `Scheduler.exactAllowed()` called
  `canScheduleExactAlarms()`, which is **API 31**, and the swallowed exception made every reminder inexact
  on API 30.

### Internal

- **`compat/WindowMetricsCompat.kt`** holds the `SDK_INT` branch for `currentWindowMetrics` /
  `maximumWindowMetrics` / `WindowInsets.Type` in one place, with a `Display.getRealMetrics` fallback.
  Twelve UI files now ask it instead of touching API 30 APIs directly.
- Every other API 28–33 call lint found is guarded: screenshot and `ACTION_IME_ENTER`, gesture exclusion
  rects, `fitInsetsTypes`, cutout mode, `blurBehindRadius`, `WindowInsetsController`, the 3-arg
  `startForeground`, `ACTIVITY_RECOGNITION`, and `ImageDecoder` (with a `BitmapFactory` fallback on 8.1).
- **On API 30+ every guard takes the original branch** and `platformVersion()` returns null, so on the
  devices that already worked, the checklist and all window geometry are **byte-for-byte unchanged**.
  `lintDebug` NewApi errors **37 → 0** (10 pre-existing, unrelated errors left alone).

## Known issues

- **The 8.1–10 path has not been run on a real device.** It builds, `lintDebug` is clean and every guard
  takes the documented branch — but **no Android 8.1 / 9 / 10 device has actually installed and run this
  build here**, and that is the whole point of the change. The warning is written to be true whether or
  not anything else on those versions misbehaves; treat it as untested until someone runs it.
- **The pre-30 inset fix is reasoned from the platform's own contract, not measured on a pre-30 ROM.** The
  commit says which side the navigation bar is assumed to be on and why; that assumption is stated in the
  code rather than hidden.
- **The wake-sensitivity numbers are the project's own measurements**, from its own impostor set
  (2.21–2.59). A different voice, room or microphone will move them. 很灵敏 is the setting that trades
  safety for reach, and the picker says so.
- **Neither pet has been used for a long stretch.** Carried from v0.12.0/v0.12.1: nobody has lived with
  either body for a day, so how the pet reads over time (in the way or not, company or distraction,
  whether the 40–80 second nap is right) has not had the time to show up.
- **The pet's own picture library is Mac-only.** You can extend the Mac pet with your own image; the phone
  ships the five presets and cannot add a sixth yet.
- **The phone's pet adds about 6.6 MB to the APK** (a scaled copy of the drawings: 560 px stills, 520 px
  frames).
- **The ball's face has never been verified on real hardware here.** Carried from v0.8.1: the eyes are 3D
  capsules under perspective projection, so a flat rendering cannot stand in for the real thing.
- **What it keeps for itself is per device.** The one on your phone and the one on your Mac each have their
  own record. They do not share a notebook. This is deliberate rather than pending.
- **Nothing verifies that a key is accepted by the server it is sent to.** These packages are checked for
  the right server and the absence of credentials; whether a given CodeFlying key works against
  `baas.kuafuai.net` versus `myapp.codeflying.app` has not been exercised end-to-end.
- **The Mac still falls back silently when no server is configured.** Every package here carries one, so it
  does not arise for these downloads — but a locally built app with an empty domain resolves to the local
  backend and sends whatever key it has to `api.deepseek.com`, while the self-check reports "Configured".
- **`docs/design/inner-drive.zh-CN.md` still opens with "草案，未实现"** although the classes it describes
  are all present. That status line is the author's to change.
- **The wake threshold's margin is thin**, carried from `v0.3.2`: the eight measured judgements sit in
  1.47–2.05 with the line landing in the gap between 1.69 and 1.77 — 0.08 wide. (Still true at 标准; the
  new dial widens the *usable* range rather than the margin itself.)
- **A light generated page still fades in over a dark stage.** Carried from `v0.3.1`; the app's own
  default has been light since `v0.4.1`.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships with a single
  newline, which reads as empty. A key written into it would outrank every build setting.
- Two issues from `v0.1.0` are **unchanged and untouched**: `tools/verify_faces_lab.py` still reports
  7/16 assertions passing, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. On Android the app asks for accessibility,
overlay, notification access, SMS and call log, and it can complete a payment by tapping; on the Mac it
asks for accessibility, screen recording and notifications. The only guardrail on that path is Android's
`FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the model, not enforcement.

**On Android 8.1–10 the permission is the same but the capability is smaller** — it cannot take a
screenshot, so it cannot see the screen to act on it. It still reads the accessibility tree. Read that as
"less able to do the risky thing", not as "safer by design".

### Opening the Mac app

The `.dmg`s are signed with a local identity, not an Apple Developer ID, so Gatekeeper refuses the first
launch of a downloaded copy.

⚠️ **On macOS 15 (Sequoia) and later, "right-click → Open" no longer works** — Apple removed that
override, and most advice online still recommends it. The current route:

1. Double-click the app. It will be refused. Dismiss the dialog.
2. Open **System Settings → Privacy & Security** and scroll to **Security**.
3. There is a line naming Andee as blocked, with an **Open Anyway** button beside it.
4. Confirm, and authenticate.

That button **only appears for about an hour** after the failed launch. If it is missing, launch the app
again and go straight back to Settings.

One more thing worth knowing: the app **inside** the mounted dmg carries no quarantine flag, so it may
launch straight from the dmg — and then be blocked once you drag it to Applications, which does attach
one. Both behaviours are normal; neither means a damaged download.

### What you supply

No package has a key. After installing, open **Settings → Backend** and either paste a CodeFlying key
(sign up from the link in that panel) or switch to **on-device** and give it an OpenAI-compatible
endpoint and model.

**For voice, a key alone may not be enough.** If you use Volcengine, the service must be an *entitled*
resource, not just an opened one — see
[docs/getting-started.md](../getting-started.md). Android can also use the system voice instead, and
without any voice it is silent but still works on screen.

> **Would you rather not configure keys at all?** Use the one-click page instead —
> **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you want,
> tap the build button, and you get a package with the **tokens already configured** plus a QR code to
> scan. Starting is free and the free token allowance is **finite — once it runs out, tokens must be
> bought.** It is a separate service with no direct relationship to this project, with its own terms,
> pricing and data handling. Note it produces **an Android APK, not a Mac app** — macOS packages can
> only be built on macOS.

## Install from source

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.13.0

# one variant, by hand:
./gradlew :app:assembleDebug -PdefaultLang=en -PcodeflyingDomain=myapp.codeflying.app -PcodeflyingSsl=true

# or all ten files, the way the release was built:
bash ~/.workbuddy/skills/andee-release-ship/scripts/build_variants.sh
```

`-PcodeflyingKey=` and `-PgoogleVoiceKey=` are refused on purpose — a published package carries no
credential.

There is a getting-started guide: **[docs/getting-started.md](../getting-started.md)**, and
**[docs/getting-started.zh-CN.md](../getting-started.zh-CN.md)** in Chinese.

**Upgrading:** `versionCode` moves `25 → 26`, so the Android package installs over v0.12.1 normally. The
Mac app's version string follows the same number. Existing memory, notebook, todos and chat history are
untouched. **On Android 11 or later nothing about the app changes** — every new guard takes the branch that
was already being taken. Your wake phrase threshold is unchanged at 标准.
