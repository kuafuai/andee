# v0.17.0

**Thinking is a property of the work now, not of what triggered the turn — and the phone's voice input is
press-to-talk.**

Two things also stopped being hard to trust: **a direct question could be answered silently**, and **a wait
that had gone stale looked exactly like one that was still live**.

> **These binaries carry no credentials.** No CodeFlying key, no voice-provider key, and no Google key.
> **You supply your own**: sign up from the link inside the app, then paste the key into
> **Settings → Backend**. Starting is free and the free allowance is finite.
>
> Each package already points at the right server for its language — the English ones at
> `myapp.codeflying.app`, the Chinese at `baas.kuafuai.net`. You do not choose this.
>
> **The macOS packages are signed with a local identity, not an Apple Developer ID**, so Gatekeeper
> refuses the first launch. On macOS 15 the old "right-click → Open" trick no longer exists; see
> **[Opening the Mac app](#opening-the-mac-app)**.

## Highlights

- **Thinking is `自动` / `开启` / `关闭`** in Settings, and it is chosen by **what the work is** rather than by
  what set it off. Unset means **`auto`**, which sends neither field and lets the model decide.
- **The phone's mic is press-to-talk** — hold to speak, release to send, and a cancel gesture ends it
  without sending.
- **A direct question is now answered aloud, mechanically.** Even if the model writes `[quiet]`, it is
  stripped — unless **you** asked for silence.
- **A wait older than 48 hours is marked `(stale)`**, so the model can see it and judge whether it still
  matters. The nightly review may now tidy the notebook.

## What's Changed

### Added

- **Thinking is `auto` / `on` / `off`, and it belongs to the work rather than to the trigger.**
  `llm_thinking` and `llm_reasoning_effort` are **shared by local and CodeFlying on both bodies** (a hub owns
  its own settings), and **unset or unreadable is `auto`** — an old explicit `enabled` / `disabled` still
  survives an upgrade.
  - **`auto` omits both fields.** There is no portable `thinking.type=auto`, so the selected model or
    backend applies its own default. `on` sends `enabled` with an optional high / medium / low; `off` sends
    `disabled`.
  - **Reviews, harvests and heartbeat work turns use that same setting.** The old `noThinking = internal`
    meant **the trigger decided, not the task** — which is exactly what this release changes. The narrow
    low-latency paths (the one-shot tool-less heartbeat verdict, `PlanMind`, `Locator`, notification triage)
    stay **explicitly disabled because those tasks are lightweight**, not because a notification or a
    heartbeat set them off.
  - **A thinking reply's `reasoning_content` stays on the assistant message for replay.** Current DeepSeek's
    tool-using thinking contract requires earlier reasoning and returns **400** when it is absent, and the
    old `sanitizeAssistant` discarded it — **which is why silent turns had been forced non-thinking at all**.
    Recovery is deliberately narrow: on a **400 that explicitly names `reasoning_content`**, and only with
    tools and a non-disabled setting, `LlmClient` retries **that one request** with thinking disabled, the
    identical messages and tools, and no effort field. It **never invents reasoning, rewrites those words as
    a user utterance, drops history, or changes the saved setting**; `Reply.thinkingFallback` makes
    `LocalBrain` log the degradation, and the next request tries the saved choice again.
- **The phone's voice input is press-to-talk.** A held input-strip button is deliberately **not** a toggle:
  the typing Activity stays up until you release, and a second press **cannot switch off a session this
  press did not start**. The transcript still goes through the one `onTranscript` path, so **exit commands
  and both brains behave exactly as they do for a ball-initiated voice turn**. The cancel gesture ends it
  without sending.
- **Stale waits are marked, and the nightly review may tidy the notebook.** A wait older than **48 hours** is
  shown as **`(stale)`** in the task line the model reads, and the person card shows **the age in days** for
  「在等他」 entries. The review rules gain an item that makes tidying **its own judgement rather than a
  rule**:
  - a memory about something now finished, or a preference that has changed → forgotten, or overwritten
    under the same name;
  - **a wait marked stale gets the question "does this still matter?"** — and the task is closed **only if
    the answer is no**.

  **The device supplies the facts (the markers and the age); the model makes the judgement.** That split is
  the point: the machine says what it can see, the model decides what it means.

### Fixed

- **A direct question is answered audibly — mechanically, not merely asked to be.** `submit(...,
  allowQuiet = false)` is the default now. The phone and the Mac pass `true` **only when the user's own
  explicit 「别出声」 / "do it quietly"** is recognised; otherwise `quietAllowed` refuses to latch the quiet
  state, **so even a model-written `[quiet]` is stripped** and narration, the spoken answer and the
  follow-up mic all carry on. **A ball that says nothing to a direct question looks broken.**
  - **The constant system prompt is not rewritten per turn** — that would throw away the prefix cache — so
    the turn-specific rule rides on the user message instead.
  - Device-initiated turns still choose quiet by judgement: when the result is already where it will be seen
    (stage, page, notebook), late at night, or when the user has said they are busy. The two default todos
    (`MORNING_TODO`, `NIGHTLY_PICTURE`) remain the exception that is **not** left to judgement — their text
    tells the model to open with `[quiet]`, because the user asked for those to run quietly.

## Known issues

- **The `reasoning_content` retry is not a live verification.** `LlmClientThinkingTest` covers the
  restored- and harvested-history path **against a local fake server**, pinning the actual request bodies.
  Whether current DeepSeek or CodeFlying accepts a replayed reasoning field in **your** account and model
  has not been exercised end to end here — the test proves the request shape, not the provider's answer.
- **`auto` means the backend decides, so behaviour will differ between models.** That is the intent, but it
  also means **"thinking is off" is not what `auto` guarantees** — pick 关闭 if you want it off for certain.
  Effort is drawn only for a forced 开启.
- **Press-to-talk has not been used on a real device for a long session.** The wiring is deliberate about
  not becoming a toggle and the transcript path is the existing one, but a held-button interaction is
  exactly the kind that fails in ways a short test does not show.
- **The nightly tidy runs on the model's judgement**, so **it can forget something you wanted kept**. The
  notebook rows it changes are still visible and editable, and 记忆 remains deletable one by one — but
  this release gives it a standing invitation to tidy, which it did not have before.
- **The 48-hour stale marker is a fixed threshold**, not a learned one, and a wait can be genuinely live
  past 48 hours. It is a marker the model sees, **not an automatic close** — nothing closes on the clock
  alone.
- **Android 8.1–10 still cannot see the screen** (v0.13.0), and that path still has not been run on a real
  8.1–10 device.
- **The Mac screenshot fix (v0.14.2) still has not been run on the machine that had the problem** — a
  3024×1964 XDR MacBook.
- **The Mac notification fixes (v0.16.1) were never exercised against the apps that provoke them.** A
  Feishu message folded in place has not been watched through to a timeline row here, and 干完回到前台 has
  not been driven by a real task from another app on this machine. It is also **off by default**, so that
  bug still exists for anyone who has not turned it on.
- **A delegated job has not been run end to end by a real user on a phone** (v0.16.0), and `dsh` must be
  installed with its key entered for the Mac side to work. Using the Mac's agent from the phone needs both
  on the same Wi-Fi with the Mac awake, and **the agent switch is off by default and per device**.
- **Recorded flows are local-only** and unencrypted beyond the notebook's own storage (v0.16.0).
- **Neither pet has been lived with for a day**, and the pet's picture library is Mac-only (v0.12).
- **The ball's face has never been verified on real hardware here.** Carried from v0.8.1: the eyes are 3D
  capsules under perspective projection, so a flat rendering cannot stand in for the real thing.
- **What it keeps for itself is per device.** The one on your phone and the one on your Mac each have their
  own record. They do not share a notebook.
- **Nothing verifies that a key is accepted by the server it is sent to.** These packages are checked for
  the right server and the absence of credentials; whether a given CodeFlying key works against
  `baas.kuafuai.net` versus `myapp.codeflying.app` has not been exercised end-to-end.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships with a single newline,
  which reads as empty. A key written into it would outrank every build setting.
- Two issues from `v0.1.0` are **unchanged and untouched**: `tools/verify_faces_lab.py` still reports
  7/16 assertions passing, and the debug WebSocket server (`net/BodyWsServer`) still binds `0.0.0.0:9008`
  with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. On Android the app asks for accessibility,
overlay, notification access, SMS and call log, and it can complete a payment by tapping; on the Mac it
asks for accessibility, screen recording and notifications. The only guardrail on that path is Android's
`FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the model, not enforcement.

**One thing in this release is worth a plain sentence.** The nightly review can now **tidy your notebook on
its own judgement** — forgetting a memory it decides is finished, or closing a task whose wait has gone
stale. That is a real grant of latitude, and it is the reason the stale markers are shown to it rather than
handled by a rule: the model is asked to judge, not told to delete. Everything it touches stays visible and
deletable.

### Opening the Mac app

The `.dmg`s are signed with a local identity, not an Apple Developer ID, so Gatekeeper refuses the first
launch of a downloaded copy.

⚠️ **On macOS 15 (Sequoia) and later, "right-click → Open" no longer works** — Apple removed that
override, and most advice online still recommends it. The current route:

1. Double-click the app. It will be refused. Dismiss the dialog.
2. Open **System Settings → Privacy & Security** and scroll to **Security**.
3. There is a line naming Andee as blocked, with an **Open Anyway** button beside it.
4. Confirm, and authenticate.

That button **only appears for about an hour** after the failed launch. If it is missing, launch the app
again and go straight back to Settings.

One more thing worth knowing: the app **inside** the mounted dmg carries no quarantine flag, so it may
launch straight from the dmg — and then be blocked once you drag it to Applications, which does attach
one. Both behaviours are normal; neither means a damaged download.

### What you supply

No package has a key. After installing, open **Settings → Backend** and either paste a CodeFlying key
(sign up from the link in that panel) or switch to **on-device** and give it an OpenAI-compatible
endpoint and model.

**For voice, a key alone may not be enough.** If you use Volcengine, the service must be an *entitled*
resource, not just an opened one — see
[docs/getting-started.md](../getting-started.md). Android can also use the system voice instead, and
without any voice it is silent but still works on screen.

> **Would you rather not configure keys at all?** Use the one-click page instead —
> **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you want,
> tap the build button, and you get a package with the **tokens already configured** plus a QR code to
> scan. Starting is free and the free token allowance is **finite — once it runs out, tokens must be
> bought.** It is a separate service with no direct relationship to this project, with its own terms,
> pricing and data handling. Note it produces **an Android APK, not a Mac app** — macOS packages can
> only be built on macOS.

## Install from source

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.17.0

# one variant, by hand:
./gradlew :app:assembleDebug -PdefaultLang=en -PcodeflyingDomain=myapp.codeflying.app -PcodeflyingSsl=true

# or all ten files, the way the release was built:
bash ~/.workbuddy/skills/andee-release-ship/scripts/build_variants.sh
```

`-PcodeflyingKey=` and `-PgoogleVoiceKey=` are refused on purpose — a published package carries no
credential.

There is a getting-started guide: **[docs/getting-started.md](../getting-started.md)**, and
**[docs/getting-started.zh-CN.md](../getting-started.zh-CN.md)** in Chinese.

## Easiest: one-click build with the tokens already set up

**The packages above carry no credentials** — you supply your own. If you would rather not,
[CodeFlying](https://www.codeflying.app/andee) builds one for you: describe what you want, tap the build
button, and you get an installable package with **the model and voice tokens already configured**, plus a
QR code to scan. Nothing to compile, and no keys to sign up for.

**New accounts get a free token allowance** — enough to get started. It is **finite: once it runs out,
tokens must be bought.** (中文：[codeflying.net/andee](https://www.codeflying.net/andee))

CodeFlying is a **separate service with no direct relationship to this project**, with its own terms,
pricing and data handling. It produces **an Android APK, not a Mac app** — macOS packages can only be
built on macOS, so use the `dmg` files above for a Mac.

**Upgrading:** `versionCode` moves `32 → 33`, so the Android package installs over v0.16.1 normally. The
Mac app's version string follows the same number. Existing memory, notebook, todos and chat history are
untouched. **Your thinking setting is preserved**: an old explicit 开启 / 关闭 survives as-is, and a device
that never set it now gets **自动** (the backend decides) rather than a forced on. **On the phone the mic
button is hold-to-talk now** — a press that used to toggle starts on press and sends on release instead.
