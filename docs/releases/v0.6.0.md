# v0.6.0

**The assistant now has a second body.** Andee runs on macOS on the same brain as the phone — the agent
loop, the memory, the notebook, the tools and the face are one implementation, and each body supplies
only the parts that are genuinely its own. Two devices that run it can also be **friends**: they pair by
QR code and ask each other for help, on-body, over an encrypted link with no server in between.

Two things changed that are easy to miss, so they are named here rather than buried: **a fresh install
now starts on CodeFlying** rather than on-device, and the Mac app exists at all.

> **These binaries are unsigned or locally signed, and bare.** The APK is the `debug` build — the release
> build type has no `signingConfig` and this repository has no keystore, so `assembleRelease` emits an
> APK that will not install until you sign it. The two `.dmg`s are signed with a **local identity, not an
> Apple Developer ID**, so Gatekeeper blocks the first open of a downloaded copy: **right-click Andee →
> Open**, or System Settings → Privacy & Security → **Open Anyway**. Once. After that, and after every
> update signed the same way, Accessibility and Screen Recording stay granted. Removing that step needs a
> Developer ID ($99/year) and notarization, which this project does not have.
>
> All binaries are built with **no keys configured** — no CodeFlying key, no voice-provider key. See
> **[Download](#download)** for what that means and what to supply yourself.

## Highlights

- **A Mac app.** The same assistant, with a floating ball above every window, the same cards, the same
  voice, the same memory — plus the hands a Mac has: mouse and keyboard, any app's accessibility tree,
  the screen, notifications, and **a sandboxed terminal**.
- **Friends.** Two Andees pair by scanning a QR code, one-time and expiring in two minutes, and the code
  carries the showing device's key fingerprint so the scanner pins that key and no other. After that
  every link is a signed handshake with forward-secret session keys.
- **Two kinds of friend, and the difference matters.** *My device* — another of your own; its requests
  run as your own. *Friend* — somebody else's; you are asked first, and the work runs with **no memory,
  no history, no vault, no personal data and no terminal**.
- **CodeFlying is the default backend on a fresh install.** The tab always leads and says the same thing
  with or without a key: what it is, how to get one, and a link.
- **One number for both bodies.** The Mac's version is read from the phone's `versionName`.

## What's Changed

### Added

- **The Mac app** (`desktop/`, Compose Desktop, macOS 14+, Apple silicon **or** Intel). A floating ball
  above every window; the same chat, settings, self-check, notebook, scenes, expressions, artifacts,
  topic and vault cards as the phone, as a sidebar with a glass panel on a real backdrop; voice in and
  out through the same four engines as Android; notifications read and triaged the way the phone does;
  mouse, keyboard, screen and window access through the accessibility API; screenshot and screen-region
  zoom with the same grid and crosshair; and **a sandboxed terminal** (`run_command`) as one of its
  hands, with a policy file and a trash broker rather than a blanket shell.
- **`:core`, a platform-neutral module.** The brain loop, the four voice engines, the notebook's logic,
  the tool schemas, the emotion-ball renderer and the wire types moved out of `app/` so both bodies
  share one implementation. `BrainHost` is the interface a body implements; the brain never sees an
  Android or a desktop type. A golden-text test pins the model-facing strings **before** the split, so a
  refactor that changes what the model reads fails loudly instead of quietly.
- **Friends** (`core/peer/`). Pairing is a one-time QR code (two minutes, three tries) whose payload
  names the shower's key fingerprint, so the scanner pins that key and no other. Every link afterwards
  is a signed handshake against pinned keys with forward-secret session keys; replayed, altered or
  reordered frames drop the link. Off until switched on. Discovery is mDNS (JmDNS on the Mac,
  `NsdManager` on the phone) plus the last address that worked, because mDNS does not always arrive.
- **`device.permissions.request`** on the Mac — asks for what a task needs, and explains the grant in
  System Settings when macOS will not show the prompt itself.
- **Long jobs handed to the clock** on both bodies, so a slow task stops holding the conversation.
- **A way out of the key rows** on both settings cards — switching to CodeFlying from wherever you are.
- **GitHub and Discord links** from the gesture line, and a Chinese half for `docs/permissions`.

### Changed

- **CodeFlying is the default backend on a fresh install.** The previous rule hid the CodeFlying tab
  unless the build was configured for it, and started on-device. Now the tab always leads, is what a
  fresh install starts on, and says the same thing with or without a key. The key row is always visible
  with show/hide and copy, and displays the key **in effect** — saving it back unchanged stores nothing,
  so a build's key is not pinned as an override. **A build with no server configured, like the ones
  attached here, has nowhere to send and says so** until a key is typed or another backend is picked.
- **The Mac reads CodeFlying's build settings from `local.properties`**, like the phone — a generated
  properties resource rather than a `BuildConfig`, because a JVM app has none.
- **The project now describes itself as two bodies on one brain.** The READMEs, `CLAUDE.md` and
  `docs/permissions` were rewritten to say so, and the permission tables gained a row for what a
  friend's request can and cannot reach.

### Fixed

- **The ball stops repainting a still window**, and the GPU draws it again — an idle-cost fix on the Mac
  that also stopped leaking ball threads.
- **A tap-to-talk path on the Mac** where the microphone opened but nothing listened.
- **A long task no longer empties the history**, a new request interrupts the old one instead of queueing
  behind it, and voice ends on silence rather than on a timeout.
- **Words typed or spoken over a question card answer it** instead of starting a new turn.
- **A notebook save that did not happen now fails** instead of answering "Saved."
- **A todo set from a notification stays untrusted when it fires**, the same rule its creation had.
- **Silent reviews no longer ask for thinking**, which was spending reasoning tokens on a turn nobody
  reads.

## Download

### macOS (macOS 14 or later)

The architecture is **not** a universal binary — an Apple silicon build will not start on an Intel Mac,
and the other way round. Take the one that matches:

| File | Take it if |
|---|---|
| `Andee-0.6.0-arm64.dmg` | an Apple silicon Mac (M1 and later) — **most Macs** |
| `Andee-0.6.0-x64.dmg` | an Intel Mac |

Open the `.dmg`, drag **Andee** to Applications, then launch it. Gatekeeper blocks the first open — see
the note at the top. It asks for **Accessibility** and **Screen Recording**; without them it runs but
cannot act on other apps or capture the screen.

### Android (Android 11 / API 30 or later)

The APK is **per-ABI**, so pick the file that matches your device:

| File | Take it if |
|---|---|
| `andee-0.6.0-debug-arm64-v8a.apk` | anything bought in the last several years — **almost everyone** |
| `andee-0.6.0-debug-armeabi-v7a.apk` | an older 32-bit device |
| `andee-0.6.0-debug-x86_64.apk` | an emulator |

### These builds are deliberately bare

Built from source with nothing configured — **verified against the generated config, not assumed**. No
CodeFlying key, no voice-provider key, no private endpoint or model name:

- CodeFlying is the backend a fresh install starts on, but **with no server configured it has nowhere to
  send** — the self-check says exactly that, and nothing is pre-wired to anyone's backend.
- **The voice provider comes up on Volcengine**, with no provider key of any kind baked in.
- The phone's default language is **English** for a device that has never picked one; the Mac's follows
  its language switch.
- The thinking default is off.

### What you have to supply

**On Android**, the assistant cannot do anything until it has a brain. Either put a CodeFlying key in
**⚙ → Backend → CodeFlying**, or pick **on-device** and give it an OpenAI-compatible endpoint and model
(an English UI defaults to `https://api.openai.com/v1` and `gpt-4o-mini`; a Chinese UI to
`https://api.deepseek.com` and `deepseek-flash`). A voice key is optional — without one the assistant is
silent but still works on screen, and the voice exit still works, because it is matched from recognized
speech rather than from the model.

**On the Mac**, it is the same two decisions in the same card.

Then, on Android in this order: grant **Overlay** → enable **Accessibility** → tap the ball. On the Mac:
launch it, and grant Accessibility and Screen Recording when it asks. Until the keys are in, the card
will name what is missing — that is the self-check working, not a fault.

> **Would you rather not configure keys at all?** Then these binaries are the wrong door — they are for
> people who want to run their own. Use the one-click page instead —
> **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you want,
> tap the build button, and you get a package with the **tokens already configured** plus a QR code to
> scan. Starting is free and the free token allowance is **finite — once it runs out, tokens must be
> bought.** It is a separate service with no direct relationship to this project, with its own terms,
> pricing and data handling. Note it produces **an Android APK, not a Mac app** — macOS packages can
> only be built on macOS.

## Known issues

- **The Mac build is signed with a local identity, so Gatekeeper blocks the first open** and there is no
  notarization. The one-step workaround is above; removing it needs an Apple Developer ID.
- **A Mac build made on another machine, without that machine's signing keychain, is ad-hoc signed** —
  its identity is locked to the build's hash, so installing it over an existing copy makes macOS treat it
  as a **different app**: Accessibility and Screen Recording must be granted again, and a stale switch
  for the old copy may sit in System Settings showing "on" while doing nothing. User data is unaffected —
  it lives outside the bundle, in `~/Library/Application Support/Andee`.
- **The two Mac downloads are not a universal binary**, and there is no lipo'd build here. Take the one
  matching your Mac.
- **Friends are new, and the discovery path is the fragile part.** mDNS is not reliable in both
  directions on every network — the Mac's resolver and Android 12's one-service-at-a-time limit were both
  worked around, and the last-good-address fallback covers the rest, but a network that blocks multicast
  entirely will not find a peer without that history.
- **A friend's request is run by a throwaway brain with no terminal and no personal data** — but it still
  acts on your screen, with your grants. The card names who is asking before the first request, and
  "always allow" is remembered per friend (`autoAccept`); there is no surface that lists what a friend
  has run, only the app log.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships empty, which is
  correct. But a local build that fills it in would be a key in a tracked file, and nothing stops that
  being committed.
- **`.gitignore` ignores `/build` at the repository root, not `build/` at any depth.** The new modules
  each carry their own `.gitignore` for this, so the tree is correct today; a module added without one
  would stage its build output on a reflex `git add`.
- **The wake threshold's margin is thin**, carried from `v0.3.2`: the eight measured judgements sit in
  1.47–2.05 with the line landing in the gap between 1.69 and 1.77 — 0.08 wide. There is still no
  quality gate on enrolment takes.
- **A light generated page still fades in over a dark stage.** Carried over from `v0.3.1`; the app's own
  default has been light since `v0.4.1`.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing, and the debug WebSocket server
  (`net/BodyWsServer`) still binds `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. On Android the app asks for accessibility,
overlay, notification access, SMS and call log, and it can complete a payment by tapping; on the Mac it
asks for accessibility, screen recording and notifications. The only guardrail on that path is Android's
`FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the model, not enforcement.

## Install from source

**Android:**

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.6.0
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

**macOS** (Apple silicon, macOS 14+, Command Line Tools):

```bash
./gradlew :desktop:createDistributable   # → desktop/build/compose/binaries/main/app/Andee.app
./gradlew :desktop:packageDmg            # → a .dmg
```

An Apple silicon Mac can build **both** architectures — the arch is decided by whichever JVM runs
Gradle, and Rosetta runs an x86_64 one. The README's Quick start has the two-chip recipe, including the
`createRuntimeImage` trap that silently produces a mixed binary. To reproduce the attached builds, leave
`local.properties` with no `CODEFLYING_*` keys and no `GOOGLE_VOICE_*` keys.

**Upgrading from v0.5.3:** `versionCode` moves `12 → 13`, so the APK installs normally. The Mac app
never existed before, so there is nothing to upgrade on that side. **The one change to watch is
CodeFlying becoming the default backend**: an existing install keeps whatever it had saved, so nothing
stops working — it is a fresh install that starts on CodeFlying now. If you were relying on the
out-of-box behaviour being on-device, that is a deliberate change, not a regression.
