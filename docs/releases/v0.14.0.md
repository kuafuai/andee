# v0.14.0

**事 (tasks) — what it took on, until it is delivered. And a notification's turn finally knows who it came
from.**

A todo is an alarm clock. A task is a thing with an end that can outlive the turn it started in: asked in
群 B, asked the leader in 群 C, the turn ended, and the answer arrives three things later. This release is
mostly about that — and about the two things a turn was blind to: **who spoke to it**, and **who it is
allowed to touch**.

> **These binaries carry no credentials.** No CodeFlying key, no voice-provider key, and no Google key.
> **You supply your own**: sign up from the link inside the app, then paste the key into
> **Settings → Backend**. Starting is free and the free allowance is finite.
>
> Each package already points at the right server for its language — the English ones at
> `myapp.codeflying.app`, the Chinese at `baas.kuafuai.net`. You do not choose this.
>
> **The macOS packages are signed with a local identity, not an Apple Developer ID**, so Gatekeeper
> refuses the first launch. On macOS 15 the old "right-click → Open" trick no longer exists; see
> **[Opening the Mac app](#opening-the-mac-app)**.

## Highlights

- **It can now carry something across turns.** 「帮我在群里问一下老王那个报价」 used to end when the turn
  ended. It becomes a **task**, and the answer — arriving later, in a message you did not relay — is
  recognised as the answer.
- **群 B 的小王 and 群 C 的小王 are no longer the same person.** A nickname carries the conversation it
  belongs to.
- **Merges can be taken back.** Two records that turn out to be one person can be folded, and **undone for
  30 days** without losing what was written since.
- **A notification that arrived on a locked phone used to wait for the screen to come on** — the eleven
  minutes reported. That is fixed, on both bodies.
- **`在办` (what it is carrying)** replaces the old 待办 list, and shows the tasks first.

## What's Changed

### Added

- **事 (tasks) — a thing with an end, that outlives the turn it started in.**
  - **The `task` tool: `open` / `wait` / `step` / `done` / `drop`.** `wait` takes
    **`on: person | user | friend | time`** — the four kinds of thing a task can be stuck on.
  - **Where it came from is recorded by the device**, not by the model — the model's own values for its
    source and its trust are thrown away.
  - **The device recognises the answer.** A message from the person (or group) a task waits on tells the
    triage what it answers, and the turn that starts from it carries the task's record: **who asked,
    where, and to quote-reply them.**
  - **`done` means delivered.** It is refused for someone else unless this turn actually **sent
    something**; and a turn that sent something and wrote no task is **reminded once**.
  - **Trust follows the task** — through its alarm and through heartbeat turns.
  - **小本本 待办 → 在办**: tasks first (answered on top), then timed todos. Timeline rows for
    opened / waiting / answered / done / dropped, on both bodies.
- **People: one record per person.** Adding someone already known no longer creates a second record — a
  name matching a name, alias or handle (once spacing, case and emoji are gone, or one name inside the
  other) stops the write and hands them back as `possible_same`; the next write names their id, or says
  `new: true`.
  - **A channel carries the conversation a nickname belongs to** — 「小王」 in 群 B and 「小王」 in 群 C
    are not taken for each other.
  - **Merges, and taking them back.** A merge can be made by the model (with a reason) or by you from the
    person's card. **The old id still finds the person**, and it can be **taken back for 30 days** without
    losing anything written since. The review is shown the groups that look like one person, and the card
    now lists unconfirmed records — which it used to hide.
- **A notification's turn knows who it came from.** The app, the conversation, whether it is a group or
  private, the sender, and what they wrote — with WeChat's `[有人@我]` / `[N条]` tags stripped. The turn
  carries it as a bracket line on its message, and a queued turn keeps it.
  - **In a group it says to quote-reply that message and to @ only that sender.** The 群 B reply that @-ed
    somebody else was a name half remembered.
  - **Whoever spoke to us goes on record**, by the device — a private message the triage told you about or
    acted on, or any message a turn starts from. **Not** everyone in a group, and **not** a private message
    it ignored. A sender who may be someone already known is pointed out on the line, for the model to
    merge.
- **A turn sees who it may touch.** Its message carries one line per person it may involve — the sender it
  came from, and whoever an open task waits on or is for — **at most six**. Person cards, on both bodies,
  list the tasks for or waiting on them.

### Fixed

- **Waiting on you is its own kind of wait.** Measured on the phone: asked to remember a parcel number you
  would send tomorrow, it registered a **person** wait on 「他」 — one the device would try to match against
  notifications forever, shown as 在等 他. **`on: user` is now a kind**, and a person wait naming the user
  (他, 用户, their name…) becomes one. Shown as **在等 你**.
- **Something to do later is a task, not a memory.** Measured on the phone: 「周五我发你纪要，你帮我改错别字」
  was saved with `remember` — which **never comes back when it is due** and never shows you it is pending.
  Both the prompt and `remember`'s own description now say so.
- **在办 always shows both headings.** With no tasks yet the tab looked exactly like the old 待办 list, and
  the reasonable conclusion was that tasks did not exist.
- **A notification arriving on a locked phone waited for the screen to come on.** The ten-second settle ran
  on `Handler.postDelayed` — i.e. **uptime**, which stops when nobody is looking — which is where the
  eleven minutes came from. A bounded `PARTIAL_WAKE_LOCK` now covers settle through verdict (**60 s
  backstop**, depth-counted), and the held retry, on the same uptime clock, gets the same treatment.
  - **The wake lock's deadline is re-armed on every enter**, and a count past its deadline resets, so
    overlapping bursts or one missed exit can no longer leave it lapsed or never taken again
    (`AwakeCount`, with tests).
  - **Deep Doze ignores wake locks.** The self-check's battery row now says what that means for
    notifications, and a message first seen **more than 2 minutes late** on a phone without the exemption
    writes a timeline row naming the fix.
- **On the Mac, one missed file event made a notification invisible rather than late.** The store was read
  only when the watcher fired, with no fallback. **A read every 60 s now runs regardless**, and the app
  holds an App Nap exemption while it watches — `userInitiatedAllowingIdleSystemSleep`, chosen so that
  **a closed laptop is still allowed to sleep**. Both exist only while `notify` is chat or all, and are
  released when it is turned off.
- **Both bodies now log the number the question is actually about**: `reached triage Nms after posting`,
  measured against the notification's own delivered time. Every timeline row is written after that point —
  so a message that waited ten minutes and one that waited ten seconds used to look identical.
- **A held message is looked at the moment the task ends**, not on the next uptime tick. A rebind request
  that did not take, and a second outage of the listener, now write a timeline row instead of passing in
  silence.

## Known issues

- **The task lifecycle has not been run end to end with a real model.** The device side is tested
  (`AwakeCountTest` and the task/people suites), and the three prompt fixes were found by **using it on the
  phone** — but the full arc (open in one group → answer three things later → recognised → `done`) has not
  been watched through, and that arc is the whole feature.
- **Merge-undo has not been exercised over its 30 days.** The window is `UNDO_MS = 30 * 86_400_000L`; what
  a person's record looks like after a merge is undone two weeks later has not been tried.
- **The notification timing numbers are from a small sample.** The wake lock is bounded and the counts are
  tested, but "how often does a message still wait" is not something this project has measured across many
  devices — and **Deep Doze on an unexempted phone can still delay a notification**, which is now logged
  rather than hidden.
- **Android 8.1–10 still cannot see the screen.** Added in v0.13.0: the app installs and runs there, but
  screen capture, visual tap targeting and window blur need API 30+. The self-check names it. **That path
  still has not been run on a real 8.1–10 device.**
- **The pet's picture library is Mac-only**, and **neither pet body has been lived with for a day** (v0.12).
- **The phone's pet adds about 6.6 MB to the APK.**
- **The ball's face has never been verified on real hardware here.** Carried from v0.8.1: the eyes are 3D
  capsules under perspective projection, so a flat rendering cannot stand in for the real thing.
- **What it keeps for itself is per device.** The one on your phone and the one on your Mac each have their
  own record. They do not share a notebook. This is deliberate rather than pending.
- **Nothing verifies that a key is accepted by the server it is sent to.** These packages are checked for
  the right server and the absence of credentials; whether a given CodeFlying key works against
  `baas.kuafuai.net` versus `myapp.codeflying.app` has not been exercised end-to-end.
- **The Mac still falls back silently when no server is configured.** Every package here carries one, so it
  does not arise for these downloads — but a locally built app with an empty domain resolves to the local
  backend and sends whatever key it has to `api.deepseek.com`, while the self-check reports "Configured".
- **`docs/design/inner-drive.zh-CN.md` still opens with "草案，未实现"** although the classes it describes
  are all present. That status line is the author's to change.
- **The wake threshold's margin is thin**, carried from `v0.3.2` — still true at 标准; the v0.13.0 dial
  widens the usable range rather than the margin itself.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships with a single newline,
  which reads as empty. A key written into it would outrank every build setting.
- Two issues from `v0.1.0` are **unchanged and untouched**: `tools/verify_faces_lab.py` still reports
  7/16 assertions passing, and the debug WebSocket server (`net/BodyWsServer`) still binds `0.0.0.0:9008`
  with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. On Android the app asks for accessibility,
overlay, notification access, SMS and call log, and it can complete a payment by tapping; on the Mac it
asks for accessibility, screen recording and notifications. The only guardrail on that path is Android's
`FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the model, not enforcement.

**Tasks change what it may do without asking, not what it may do at all.** A task carries the trust of the
turn it came from, so an answer arriving later does not quietly get more permission than the request that
started it. The line about who a turn may touch is a limit on what it names, not a grant — **at most six
people**, and none of them gains a permission the turn did not already have.

### Opening the Mac app

The `.dmg`s are signed with a local identity, not an Apple Developer ID, so Gatekeeper refuses the first
launch of a downloaded copy.

⚠️ **On macOS 15 (Sequoia) and later, "right-click → Open" no longer works** — Apple removed that
override, and most advice online still recommends it. The current route:

1. Double-click the app. It will be refused. Dismiss the dialog.
2. Open **System Settings → Privacy & Security** and scroll to **Security**.
3. There is a line naming Andee as blocked, with an **Open Anyway** button beside it.
4. Confirm, and authenticate.

That button **only appears for about an hour** after the failed launch. If it is missing, launch the app
again and go straight back to Settings.

One more thing worth knowing: the app **inside** the mounted dmg carries no quarantine flag, so it may
launch straight from the dmg — and then be blocked once you drag it to Applications, which does attach
one. Both behaviours are normal; neither means a damaged download.

### What you supply

No package has a key. After installing, open **Settings → Backend** and either paste a CodeFlying key
(sign up from the link in that panel) or switch to **on-device** and give it an OpenAI-compatible
endpoint and model.

**For voice, a key alone may not be enough.** If you use Volcengine, the service must be an *entitled*
resource, not just an opened one — see
[docs/getting-started.md](../getting-started.md). Android can also use the system voice instead, and
without any voice it is silent but still works on screen.

> **Would you rather not configure keys at all?** Use the one-click page instead —
> **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you want,
> tap the build button, and you get a package with the **tokens already configured** plus a QR code to
> scan. Starting is free and the free token allowance is **finite — once it runs out, tokens must be
> bought.** It is a separate service with no direct relationship to this project, with its own terms,
> pricing and data handling. Note it produces **an Android APK, not a Mac app** — macOS packages can
> only be built on macOS.

## Install from source

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.14.0

# one variant, by hand:
./gradlew :app:assembleDebug -PdefaultLang=en -PcodeflyingDomain=myapp.codeflying.app -PcodeflyingSsl=true

# or all ten files, the way the release was built:
bash ~/.workbuddy/skills/andee-release-ship/scripts/build_variants.sh
```

`-PcodeflyingKey=` and `-PgoogleVoiceKey=` are refused on purpose — a published package carries no
credential.

There is a getting-started guide: **[docs/getting-started.md](../getting-started.md)**, and
**[docs/getting-started.zh-CN.md](../getting-started.zh-CN.md)** in Chinese.

**Upgrading:** `versionCode` moves `26 → 27`, so the Android package installs over v0.13.0 normally. The
Mac app's version string follows the same number. Existing memory, notebook, todos and chat history are
untouched — **and the notebook's 待办 tab is now 在办.** Nothing is lost: promises and a person's owed
items were **moved into tasks once**, with the originals kept. **`在办` always shows both headings**, so a
notebook with no tasks yet no longer looks like the tab stopped working.
