# v0.1.1

**Five fixes, and three of them are about the app telling you the truth.** Nothing new was added; this
release removes a screen that fought another one, corrects four sentences that sent users to menu
labels that do not exist, and fixes the one failure that could lock a user out of the app entirely.
Still no binary attached — see *Install* below.

> **No APK is attached to this release, on purpose.** The release build type has no `signingConfig`
> and there is no keystore in this repository, so `assembleRelease` emits
> `app-<abi>-release-unsigned.apk`, which will not install until you sign it. Shipping a binary a
> reader cannot install would be worse than shipping none. Build it yourself — see *Install* below.

## Highlights

- **The launcher icon can no longer become a dead end.** On some ROMs (HONOR/MagicOS, measured on
  LIO-TL00) a denied overlay grant does not make `addView` fail — it succeeds and the system hides
  the window, so the view object stays around and `isShown()` keeps answering true. The entry test
  trusted that marker, took the "expand the ball" branch, and finished on an empty screen: the icon
  did nothing, and did it again every time. The grant is now asked **directly**,
  `Settings.canDrawOverlays()`, the same predicate the self-check's own 悬浮窗 row uses — so the page
  and the door can no longer disagree.
- **Four strings stop pointing at menus that are not there.** The settings card was reorganised twice
  since those sentences were written and the sentences stayed behind: they said ⚙ → 「大脑」 / "Brain"
  when the section reads 「后端」 / "Backend", one named a 语音（火山引擎） section that no longer
  exists, and one told the user to long-press the ball to open settings — which expands the card, it
  does not open settings.
- **A picture, a video or a clip now goes into a page instead of being handed over as a URL.** The
  prompt forbade embedding media on a false premise ("this device cannot turn an image into a URL").
  It is false for anything on the network, so the model was obeying its instructions and handing the
  user a link to open on the device they were already holding.
- **The first-run wizard is gone, and the self-check kept the card.** Both wanted to put a card up on
  a first start; when the check found a problem it covered the wizard, so a new user saw whichever
  lost the race.

## What's Changed

### Fixed

- **The launcher icon could become a permanent dead end.** See *Highlights*. `ensureOverlays()` and
  `showSelfCheckCard()` now ask `Settings.canDrawOverlays()` before anything else; `SelfCheckActivity`
  falls through to the checklist — the page that names this failure in red — instead of expanding a
  card that cannot be drawn. Verified on a device on **both** paths: grant denied now reaches the
  checklist (13 activity records), grant allowed still takes the expand branch (0 records).
- **Four strings named menu labels that do not exist, and one a gesture that does not exist either.**
  `check_detail_brain_key_missing`, `check_detail_brain_hub_missing` and `brain_no_key` said
  ⚙ → 「大脑」 / "Brain"; the header is `settings_section_brain` = 「后端」 / "Backend".
  `check_detail_voice_key_missing` named a 语音（火山引擎） section whose rows had moved into
  后端 → 本机. `brain_no_key` also said 长按小球打开设置 (*"long-press the ball to open settings"*) —
  a long-press calls `dispatcher.expand()`, which brings the card back; settings is the ⚙ button in
  that card's control bar, and the sentence now names both steps. `check_detail_brain_hub_missing`
  gained the precondition it was missing: **「云端」 is hidden unless 高级 →「显示云端选项」 is on.**
- **Both READMEs promised a first-run wizard that no longer exists** — "The first run is a stepped
  setup that walks you through both" / 「第一次启动会有一个分步引导」. A missing setup guide is
  indistinguishable from a broken install, so this read as a bug report rather than as stale prose.
  Both now describe what the app actually does: the self-check runs on every start, the card names
  the missing key, and its button opens settings.
- `README.md` named the Volcengine field as **火山 API key** — the Chinese label — while the English
  build displays **Volcengine API key**. Only the English file was wrong.
- **A picture, a video or a clip goes into a page now.** §7 asks for the embedding directly
  (`<img>`, `<video controls>`, `<audio controls>`, absolute `https://` only) and says outright that
  passing over a bare URL is not an answer; the `show_html` description carves media out of its
  self-contained-shell rule for the same reason. Verified by compiling and reading both strings back
  out of the compiled classes. **Not verified on a device** — none was attached, so a real `https`
  image and a real `.mp4` rendering in the page are unconfirmed.

### Changed

- **The 悬浮窗权限 row now leads the self-check list**, ahead of 无障碍服务. Both are hard gates and
  the order between them was arbitrary; they fail in opposite directions, and that settles it. With
  the service off the app is visibly inert. With the grant off it *looks* broken instead — the
  service runs fine, silently cannot draw, and tapping the icon appears to do nothing. That second
  shape is the one users misread as "the app is dead", so it goes first.
- 无障碍服务's off-state copy no longer names its own list position — 「后面几条都不用看」 /
  "the rest of this list does not matter yet" became 「其他都不用看」 / "nothing else here matters
  either". Same meaning, no longer invalidated by the reorder. Both string files.

### Removed

- **The first-run wizard** — `ui/FirstRunUi.kt`, its wiring in `ScreenBodyService`, the 重新设置 button
  on the self-check card, and its strings in both languages. The wizard and the startup self-check
  both wanted to put a card up on a first start, and when the check found a problem it covered the
  wizard, so a new user saw whichever lost the race; the wizard was removed rather than arbitrate
  between the two. The self-check's own prefs file stays, as does `PermissionRequestActivity`, which
  the check still uses. An old `wizard_done` flag on existing installs is simply never read. The wake
  word is now offered only from settings and as a note row on the self-check.
- `check_page_no_overlay` and the `SelfCheckUi.note()` helper it was the only caller of. The note
  explained that the settings sheet is drawn as an overlay — a fact the page does not need to teach,
  because the 悬浮窗 row directly below it already carries the fix, in its own words and with a
  button.

## Known issues

- **A build with CodeFlying compiled in but no API key can raise the wrong complaint.** The
  self-check's availability test looks at `CODEFLYING_ENABLED` and the domain rather than the key, so
  such a build reports 大脑 key missing and sends the user to fill in a DeepSeek key — while the real
  cause is at build time. Surfaced by reading this release's diff; not fixed by it.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing against the committed
  `reports/ball-faces-lab.html`, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. This app asks for accessibility, overlay,
notification access, SMS and call log, and it can complete a payment by tapping. The only guardrail on
that path is Android's `FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the
model, not enforcement.

## Install

Android 11+ (`minSdk 30`), arm64-v8a for anything bought in the last several years. There is no binary
in this release; build one:

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.1.1
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

`assembleRelease` needs your own keystore — the repo has none, so it produces an unsigned APK. Either
way the APK is **per-ABI** (`splits` in `app/build.gradle`), so pick the file that matches the device.
Full from-scratch setup is in the README's **Provisioning** section. Then, in this order: grant
Overlay → enable Accessibility → tap the ball → put in your own keys under ⚙.

**Upgrading from v0.1.0:** `versionCode` moves `1 → 2`, so this installs over it normally. An old
`wizard_done` preference is left in place and never read.
