# v0.16.0

**Andee can hand a job to a coding agent and carry it as a 事 — and your phone can borrow your Mac's
agent over the link, as if it were the phone's own.**

This is the release where the two halves of the project meet: **the agent it delegates to** (`dsh`, a
DeepSeek Harness session) and **the tasks it already carried** (在办). A delegated job is not a message
that scrolls away — it is a task with a worker, with live progress, that only you can close.

It also brings **recorded flows** — the scenes' hands — and folds the README into one page.

> **These binaries carry no credentials.** No CodeFlying key, no voice-provider key, and no Google key.
> **You supply your own**: sign up from the link inside the app, then paste the key into
> **Settings → Backend**. Starting is free and the free allowance is finite.
>
> Each package already points at the right server for its language — the English ones at
> `myapp.codeflying.app`, the Chinese at `baas.kuafuai.net`. You do not choose this.
>
> **The macOS packages are signed with a local identity, not an Apple Developer ID**, so Gatekeeper
> refuses the first launch. On macOS 15 the old "right-click → Open" trick no longer exists; see
> **[Opening the Mac app](#opening-the-mac-app)**.

## Highlights

- **Hand it a job; it comes back as a 事.** `delegate_task` gives work to a DeepSeek Harness session in its
  own folder and returns at once. **What the job produced is read off the folder by the device**, not
  taken from the report's prose — the report is fenced as an untrusted turn.
- **Your phone can use your Mac's agent.** Pair them, flip one switch on the Mac, and the phone's Andee
  lists the same tools the Mac lists for its own dsh. **Off by default, per device**, and a friend's Andee
  never gets it.
- **在办 is a door of its own on both bodies** — a list, one page per task, and only you close a task.
  **A tap on the ball, a new request and clearing the chat no longer cancel a worker.**
- **Recorded flows: the scenes' hands.** A run replays locally, step by step, **with no model call per
  step** — and a stopped flow **repairs itself and saves the repair** instead of ending the conversation.
- **The README is one short page**, English above and Chinese below, with four demos at the top.

## What's Changed

### Added

- **dsh as a worker: a job handed over comes back as a task.** `delegate_task` hands a job to a DeepSeek
  Harness session (`dsh --profile sdk`) in its own folder and returns at once; the report comes back as a
  **fenced, untrusted turn**. **What a job produced is read off the folder by the device**, not from the
  report's prose. Every job is a task: the device sets a worker wait and answers it on the report
  (`Tasks.workerAnswered`). `continue=<id>` resumes the worker's session; if another dsh window holds its
  write lock, the job goes on in a **new session in the same folder**, told the old report and the files
  already there. **A tap on the ball, a new request and clearing the chat no longer cancel a worker** —
  only `delegate_cancel` does. Live progress (step, time, tokens, its own checklist, newest actions) rides
  in `DshLive`.
  - **There is deliberately no link into dsh's web window.** `dsh web` reads a running session as a dead
    turn and then holds its write lock — so the app shows progress itself rather than opening that page.
- **在办 (what it is carrying) is now a first-class door on both bodies.** The Mac gets a sidebar list
  above 话题 (answered first, then running, six at most) and one page per task with **接着办 / 说点要求再办
  / 办完了 / 放下**; 全部 lists the rest and what was finished in the last seven days. The phone gets a
  **在办 key on the top bar** (with a count, and a red dot when a task is delivered or answered) opening
  the same list and pages. **The notebook's last tab is now 定时 and keeps only the alarms**, because
  tasks have left it.
- **A phone can use the computer's agent as if it were its own.** When a paired computer offers its agent,
  the phone lists the same tools the Mac lists for its own dsh — `delegate_task`, `delegate_status`,
  `delegate_cancel`, `read_worker_file` — plus `list_worker_files` and `fetch_worker_file`. Calls go over
  the authenticated link; a file is fetched in chunks to disk and **a half-file is never kept**. A worker's
  report arrives as a turn of its own, fenced as another agent's words, and **the path to the Mac's folder
  is left out of it**.
  - **The owner's switch is per own device and off by default**, on the friends page. A friend's Andee
    never gets it, and filing a device as a friend takes it away. The Mac does not judge the call — **the
    other Andee already decided**.
  - **A job started this way belongs to that device** (`Worker.origin`): no task is opened on the Mac, the
    report goes back to that device and not to this Mac's brain, and the device sees and reads only its own
    workers, **inside their folders** — a link that leaves a folder counts as outside.
  - `about` now says whether a device offers its agent, and is re-sent when the switch changes.
- **A job handed to the computer's agent is a task on the phone too, with live progress.** The phone opens
  a 「事」 that waits on the worker the computer returned; the report answers that wait and rides on the
  report's turn with the task's record, and **a job that never started leaves no task behind**. The
  computer sends step, time, checklist and newest actions to the phone that started it at most every two
  seconds. **The agent is described to the phone's model as a capability of its own**, in a paragraph of
  its own — not as something a friend can do.
- **A worker's files are listed and opened in the app on both bodies.** The phone's 工作文件 card reads
  text **in the card** (Markdown drawn as Markdown) instead of handing it to the system, which had
  resolved `text/markdown` to **a music app that opened and closed at once**; other types go through a
  chooser, and a phone with no viewer says so. The Mac gets a page that lists the worker's folder and opens
  a file from there. **Nothing leaves the worker's folder.**
- **A task with a worker running offers 停止 dsh, and closing it asks about the worker first.** Carrying on
  or adding a requirement does nothing for a running worker — dsh takes no word mid-run, it can only be
  stopped — and 放下 / 办完了 used to close the 事 while **leaving the worker running on the user's quota
  with nobody to take its report**. While a worker runs, both bodies show 停止 dsh / 办完了 / 放下, and
  **办完了 and 放下 ask first**: stop it and close, leave it running and close, or cancel.
- **A Mac without dsh offers 让 Andee 帮我安装.** The button states, as the user would, the one fixed
  command (`npm install -g --prefix ~/.npm-global @deepseek-ai/dsh`), runs it **outside the terminal
  sandbox** through `DshInstaller`, and counts it done **only when `Bin.find` finds dsh and `dsh --version`
  starts** — npm's own "success" is not the evidence. Then it opens `dsh web` for the key, and writes one
  timeline row either way.
- **Recorded flows — the scenes' hands.** Recorded runs the device plays back step by step, **locally, with
  no model call per step**: `record_flow_start` arms recording, `wait_for_user` marks a step only the user
  can do, `save_flow` stores it in the notebook (same consent rule as scenes), and `run_flow` /
  `resume_flow` replay it. **Every step is verified before it runs** — the element must still be there, the
  app must match, and the screen must react — and a failure stops the flow with a structured `failed_at`
  instead of guessing. Flows are **local-only like scenes, never reach a hub**, and are listed on the user
  messages next to the scenes. Reported: 蔡·鱼儿's token spend on repetitive chores, **#43**.
- **A 脚本 tab on the 情景 card**, so a flow can be run straight from the card (no model involved), its
  steps inspected before it runs, and deleted with the same two-tap confirm. **A recording pill** —
  「● 录制中 · N 步」 — sits under the status bar while recording is armed; it is the one indicator that
  survives the card folding, which is exactly when recording happens.
- **A stopped flow heals itself instead of ending the conversation.** Reported: *「某一步卡住了，就得从头来，
  或者从头开始重新录」*. A replay now returns a **report**, not a boolean: the step trace, `current_screen`,
  `resume_from` and a hint. **`refit_flow` re-anchors one stale step and saves the repair into the flow**, so
  an app update no longer kills a script. **`edit_flow` can insert a step** (`launch` / `wait` / `human` /
  `type` / `tap`) — after the end-to-end test, the one thing the brain could not fix was a script that never
  opens its own app. **An `ai` step hands a step back to the brain on purpose** (`paused:true`, not a
  failure) for jobs that are not recordable gestures — a CAPTCHA, a dialog that appears only sometimes.
  A run started from the card **wakes the brain on a stop** with that report, so nobody has to say 「修」
  first. **Three takeovers on the same stuck step within two minutes stop the loop** and give an honest
  report.
- **The README is one short page now, English above and Chinese below.** Four demo videos sit at the hero
  in place of the two that were there, one paragraph each so each becomes its own player, and the long
  reference material moved into `docs/` (`reference`, `build-and-provision`, `permissions`,
  `acceptable-use`, each with a `.zh-CN` counterpart). **`README.zh-CN.md` is gone** — the language switch
  is an in-page anchor, not a second file.

### Fixed

- **A tap that changes nothing is no longer reported as a miss.** `screen_changed:false` on a refresh,
  toggle or submit used to come back as *「the screen did NOT react to this tap」*, sending the brain into a
  re-aim loop while the replay engine counted the same step as `done`. The hint now says the tap **was**
  delivered, and `relocated:true` carries an `anchor_note` so it is not mistaken for a mis-aim.
- **A background launch now opens through our own invisible stage, and Xiaomi's guard is tapped through.**
  HyperOS aborts **any** Activity start from a background app — even Andee's own — unless the launcher is
  in front, and it measures the abort window in seconds after HOME. Launches now go home via
  `GLOBAL_ACTION_HOME` (the one route the ROM executes as the system and never aborts), settle past the
  window, open through a new transparent `LaunchPadActivity`, then **verify the target actually reached the
  foreground** — retrying once before reporting. **`launch_app` returning success while nothing opened is
  gone**; so is the minutes-long loop of retry-dialog-retry.
- **A failure report now names the KIND of stop.** `failure_class` — `launch_blocked` / `wrong_screen` /
  `stale_anchor` / `screen_frozen` / `user_absent` / `bad_step` — rides in every stopped report with a
  per-class hint, so the brain acts on the machine's diagnosis instead of re-diagnosing.
- **A report taken over by your next words runs again after them instead of vanishing.** A report from the
  computer arrives as a wake turn; if your own turn started while it was running, the wake turn was
  abandoned with **no answer, no error and nothing queued** — so the report was never dealt with. A
  `WAKE` / `NOTIFY` / `PEER` turn taken over before it answered now goes back to the front of the queue.
- **The per-step app gate stopped trusting a stale cache.** `ScreenController.currentPkg()` is only the last
  tree dump's package — null, or still 「home」 after an app has already come forward. Without this, a flow
  started from the home screen either ran its taps on the launcher or reported a launch that had succeeded
  as stopped.
- **Enough 事 in hand no longer push 自检 and 设置 out of the sidebar** on the Mac. 在办 and 话题 now share
  one scrolling region that takes only the space between them.
- **The phone no longer cuts Andee's replies** at a few lines with dots — what it says is shown whole.
  A worker asked to research, compare or write something up is told to deliver **one self-contained HTML
  page** readable on a phone, rather than markdown.

## Known issues

- **A delegated job has not been run end to end by a real user on a phone.** The device side is tested, and
  the flow work was verified on the tablet (forced stop → brain woken → 8 tool calls → `done:true`), but
  the whole arc — hand a job from the phone to the Mac's agent, watch it, read its files, close it — has
  been exercised by the maintainers rather than observed in someone else's hands.
- **`dsh` must be installed and its key entered for the Mac side to work.** The app can install it for you,
  but the key step opens `dsh web` and is yours to complete. **The phone's use of the Mac's agent needs both
  devices on the same Wi-Fi and the Mac awake.**
- **The Mac's agent switch is off by default and per device.** Nothing is shared until you turn it on for a
  specific paired device — that is deliberate, but it does mean a fresh pair looks like it does nothing
  until you find the switch on the friends page.
- **Recorded flows are local-only and unencrypted beyond the notebook's own storage.** They are never sent
  to a hub, but a flow records what you did on screen, so treat the notebook as the sensitive thing it is.
- **The `ai` step and the self-heal budget are new**, and the two-minute / three-takeover loop guard is a
  **heuristic**: a genuinely stuck step will stop with a report rather than keep trying, which is better
  than a loop but is still not a fix.
- **Android 8.1–10 still cannot see the screen** (v0.13.0), and that path still has not been run on a real
  8.1–10 device.
- **The Mac screenshot fix (v0.14.2) still has not been run on the machine that had the problem** — a
  3024×1964 XDR MacBook. What was verified is that the code is the API that worked before the regression
  and that it is really in the package.
- **Neither pet has been lived with for a day**, and the pet's picture library is Mac-only (v0.12).
- **The ball's face has never been verified on real hardware here.** Carried from v0.8.1: the eyes are 3D
  capsules under perspective projection, so a flat rendering cannot stand in for the real thing.
- **What it keeps for itself is per device.** The one on your phone and the one on your Mac each have their
  own record. They do not share a notebook — **and now that one can drive the other's agent, that
  separation is a design choice worth restating.**
- **Nothing verifies that a key is accepted by the server it is sent to.** These packages are checked for
  the right server and the absence of credentials; whether a given CodeFlying key works against
  `baas.kuafuai.net` versus `myapp.codeflying.app` has not been exercised end-to-end.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships with a single newline,
  which reads as empty. A key written into it would outrank every build setting.
- Two issues from `v0.1.0` are **unchanged and untouched**: `tools/verify_faces_lab.py` still reports
  7/16 assertions passing, and the debug WebSocket server (`net/BodyWsServer`) still binds `0.0.0.0:9008`
  with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. On Android the app asks for accessibility,
overlay, notification access, SMS and call log, and it can complete a payment by tapping; on the Mac it
asks for accessibility, screen recording and notifications. The only guardrail on that path is Android's
`FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the model, not enforcement.

**Two things in this release deserve a plain sentence each.**

**A worker writes files on your machine.** `dsh` runs in a folder of its own, and the device reads what it
produced **from that folder**. The folder is the boundary: what a worker may write to is scoped, and the
phone that borrowed your Mac's agent can read only **its own** workers' folders. It is still a process
writing to your disk on your behalf — the same trust you extend to any coding tool you point at a directory.

**Your Mac's agent can now be reached from your phone.** It is **off by default**, **per paired device**,
and a friend's Andee can never reach it. Turning it on is the moment your phone can start real work on your
computer, so it is worth turning on deliberately rather than because a setup flow asked.

### Opening the Mac app

The `.dmg`s are signed with a local identity, not an Apple Developer ID, so Gatekeeper refuses the first
launch of a downloaded copy.

⚠️ **On macOS 15 (Sequoia) and later, "right-click → Open" no longer works** — Apple removed that
override, and most advice online still recommends it. The current route:

1. Double-click the app. It will be refused. Dismiss the dialog.
2. Open **System Settings → Privacy & Security** and scroll to **Security**.
3. There is a line naming Andee as blocked, with an **Open Anyway** button beside it.
4. Confirm, and authenticate.

That button **only appears for about an hour** after the failed launch. If it is missing, launch the app
again and go straight back to Settings.

One more thing worth knowing: the app **inside** the mounted dmg carries no quarantine flag, so it may
launch straight from the dmg — and then be blocked once you drag it to Applications, which does attach
one. Both behaviours are normal; neither means a damaged download.

### What you supply

No package has a key. After installing, open **Settings → Backend** and either paste a CodeFlying key
(sign up from the link in that panel) or switch to **on-device** and give it an OpenAI-compatible
endpoint and model.

**For voice, a key alone may not be enough.** If you use Volcengine, the service must be an *entitled*
resource, not just an opened one — see
[docs/getting-started.md](../getting-started.md). Android can also use the system voice instead, and
without any voice it is silent but still works on screen.

> **Would you rather not configure keys at all?** Use the one-click page instead —
> **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you want,
> tap the build button, and you get a package with the **tokens already configured** plus a QR code to
> scan. Starting is free and the free token allowance is **finite — once it runs out, tokens must be
> bought.** It is a separate service with no direct relationship to this project, with its own terms,
> pricing and data handling. Note it produces **an Android APK, not a Mac app** — macOS packages can
> only be built on macOS.

## Install from source

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.16.0

# one variant, by hand:
./gradlew :app:assembleDebug -PdefaultLang=en -PcodeflyingDomain=myapp.codeflying.app -PcodeflyingSsl=true

# or all ten files, the way the release was built:
bash ~/.workbuddy/skills/andee-release-ship/scripts/build_variants.sh
```

`-PcodeflyingKey=` and `-PgoogleVoiceKey=` are refused on purpose — a published package carries no
credential.

There is a getting-started guide: **[docs/getting-started.md](../getting-started.md)**, and
**[docs/getting-started.zh-CN.md](../getting-started.zh-CN.md)** in Chinese.

**Upgrading:** `versionCode` moves `30 → 31`, so the Android package installs over v0.15.0 normally. The
Mac app's version string follows the same number. Existing memory, notebook, todos and chat history are
untouched. **Two things move in the interface:** the notebook's last tab is **定时** now and holds only the
alarms, because tasks have a door of their own (在办); and on the Mac **在办** sits in the sidebar above
话题. A task you were carrying is still there — it just has its own place. **dsh is optional**: nothing
changes if you never install it.
