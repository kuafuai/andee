# v0.8.1

**A cuter Andee, a notebook that starts with something in it, and four fixes that came out of using it.**

The face was retuned against the reference illustrations. A fresh notebook now arrives with one todo
already in it — an evening picture of "you and me". The Mac gets the CodeFlying market. And the rest is
the kind of thing that only shows up on a real device — a key that the running brain never saw, home
gestures on the phone, and a voice handshake that failed silently.

> **These binaries carry no credentials.** No CodeFlying key, no voice-provider key, and no Google key.
> **You supply your own**: sign up from the link inside the app, then paste the key into
> **Settings → Backend**. Starting is free and the free allowance is finite.
>
> Each package already points at the right server for its language — the English ones at
> `myapp.codeflying.app`, the Chinese at `baas.kuafuai.net`. You do not choose this.
>
> **The macOS packages are signed with a local identity, not an Apple Developer ID**, so Gatekeeper
> refuses the first launch. On macOS 15 the old "right-click → Open" trick no longer exists; see
> **[Opening the Mac app](#opening-the-mac-app)**.

## Highlights

- **A new notebook already has one thing in it.** Every evening at 21:00 it looks back over the day and
  makes a picture of "you and me" with some mood to it. One todo, seeded once — if you drop or pause it,
  it does not come back.
- **The Mac has the CodeFlying market.** `market_search` and `market_call` now exist on the Mac as they
  do on the phone — and only on the CodeFlying backend, staying out of the way on any other.
- **A new face for the default Andee.** Periwinkle body with a peach rim light, bigger and darker eyes
  with two glints, rounder horns, finer meshes. It is the same character — the look's `name` is unchanged,
  so if you had picked an image, nothing moves.
- **Thinking no longer pushes the eyes off the ball.** The bigger eyes made the old drift values visible
  as an error. The drift and the slow sway are now capped so the outer eye stays on the head; quick
  actions are deliberately left uncapped.
- **A key you save is used immediately**, on the phone. Before this, saving one from the self-check sheet
  wrote the setting and changed nothing — the ball kept answering *"no key"* until the app was
  restarted.
- **Phone gestures and overlay transitions** are smoother, and a tap on the Mac that cannot reach the
  voice service now tells you why instead of failing silently.

## What's Changed

### Added

- **A fresh notebook starts with one todo**, at 21:00 every evening: look back over the day and make a
  picture of "you and me" with some mood to it. Seeded once per notebook — a meta flag stops a todo you
  dropped or paused from coming back, and a wipe (clear notebook, factory reset) takes the flag with it.
  Both bodies seed it on their start-up catch-up.
  It assumes **no particular tool and no particular language**: image generation exists only where there
  is one (CodeFlying's market), so it says to use an image tool if you have one and otherwise draw the
  picture as a page. Its text is model-facing English like every other wake-up line, and follows the
  language of your recent conversation — a notebook is seeded before anyone has said a word, so the
  interface language at that moment is the one thing that is reliably wrong.
- **The Mac has the CodeFlying market.** `MarketTools` moves to the shared core and the Mac registers it
  as a tool provider built from the brain's own config — so `market_search` / `market_call` list
  themselves **only** on the CodeFlying backend, as on the phone, and a key or backend change rebuilds
  the brain and the tools with it.

### Changed

- **The default face, retuned toward the reference illustrations.** A periwinkle body with a peach rim
  light, bigger and darker eyes with two glints, eyes and cheeks raised (`eyeY 0.09 → 0.07`) with the
  mouth left low, rounder horns, and finer meshes for the eyes, mouth, horns and props. Gloss drops
  `0.22 → 0.05` and the rim light becomes fully mixed (`0.55 → 1.0`), which is what moves it from
  plastic to matte.
- **A repeating todo is no longer closed when it comes due.** Finishing a repeating todo used to end the
  series for good — so the first evening's picture would have been the last. The wake-up line, the tool
  result and the prompt now all say so.

### Fixed

- **Thinking no longer carries the bigger eyes past the edge of the head.** The thinking drift is now
  `0.03` (was `0.075`) and the head turn it drives `0.04` (was `0.09`); the slow sway and the drift are
  capped together at `0.10 rad` so the outer eye cannot roll off the sphere. A shake or a look around is
  not capped — those are brief. Checked over 36 frames at `dp 420` and at the folded `dp 136`.
- **A key saved from the self-check sheet reaches the running brain.** Measured on a device: v0.8.0
  reinstalled at 14:30 built its brain with an empty key, self-check reported `brain:FAIL` at 14:30:34,
  the key was saved at 14:31, and the first typed sentence at 14:33 still came back *"no key"*. The brain
  reads that line from a config snapshot taken when it was constructed, and nothing re-read it. The
  self-check page can appear while the service is already running, so the path that assumed "no service,
  nothing to rebuild" was only true of one of its two entry points.
- **Home gestures and overlay navigation on the phone**: navigation boundaries are covered, and a home
  action that fails is logged instead of dropped.
- **Overlay opening and closing**, and layout during keyboard transitions, do less work per frame.
- **A refused voice handshake on the Mac reads as an error in the conversation** rather than a tap that
  silently does nothing.
- **Factory reset keeps the CodeFlying key**, on both bodies, and the confirmation now says so rather
  than leaving it to be discovered. The phone cleared it along with the rest of its settings; the Mac
  deleted it too and only *looked* as if it had kept it.
- **A cleared conversation no longer contains a line about itself.** Clearing the history stopped the
  brain first, and the stop wrote 「被你叫停了」 into the history afterwards; it now shuts the discarded
  brain down without a report.
- **Volcengine voice endpoint and resource defaults** show as hints in settings instead of looking like
  something already filled in.
- **A stale cleartext exception is gone** from both Android network security configs: CodeFlying is
  `https://baas.kuafuai.net` now, and keeping an exception for a host nobody calls only widens what the
  app may talk to in the clear.

### Documentation

- **Volcengine voice needs an entitled resource, not just a key.** A newly opened service defaults to
  post-paid and can only be used from Volcengine's own trial page — calls over the API are refused, so a
  correct key in a filled-in field still dies at the handshake. The switch is on the console's **开通管理**
  page. It is written down because both failure shapes surface as `ASR ws refused: …`, and neither
  message points at that page. Two ASR resource ids this build can use are named in the README, and
  version 2.0 is explicitly ruled out.

### Opening the Mac app

The `.dmg`s are signed with a local identity, not an Apple Developer ID, so Gatekeeper refuses the first
launch of a downloaded copy.

⚠️ **On macOS 15 (Sequoia) and later, "right-click → Open" no longer works** — Apple removed that
override, and most advice online still recommends it. The current route:

1. Double-click the app. It will be refused. Dismiss the dialog.
2. Open **System Settings → Privacy & Security** and scroll to **Security**.
3. There is a line naming Andee as blocked, with an **Open Anyway** button beside it.
4. Confirm, and authenticate.

That button **only appears for about an hour** after the failed launch. If it is missing, launch the app
again and go straight back to Settings.

One more thing worth knowing: the app **inside** the mounted dmg carries no quarantine flag, so it may
launch straight from the dmg — and then be blocked once you drag it to Applications, which does attach
one. Both behaviours are normal; neither means a damaged download.

### What you supply

No package has a key. After installing, open **Settings → Backend** and either paste a CodeFlying key
(sign up from the link in that panel) or switch to **on-device** and give it an OpenAI-compatible
endpoint and model.

**For voice, a key alone may not be enough.** If you use Volcengine, the service must be an *entitled*
resource, not just an opened one — see
[docs/getting-started.md](../getting-started.md). Android can also use the system voice instead, and
without any voice it is silent but still works on screen.

> **Would you rather not configure keys at all?** Use the one-click page instead —
> **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you want,
> tap the build button, and you get a package with the **tokens already configured** plus a QR code to
> scan. Starting is free and the free token allowance is **finite — once it runs out, tokens must be
> bought.** It is a separate service with no direct relationship to this project, with its own terms,
> pricing and data handling. Note it produces **an Android APK, not a Mac app** — macOS packages can
> only be built on macOS.

## Known issues

- **The new face was checked offscreen, not on a device.** The 36-frame sweep at `dp 420` and the folded
  `dp 136` were rendered for this release, and this project has an offscreen ball renderer and an
  assertion script alongside it — but **the face on real hardware has never been verified here**. The
  eyes are 3D capsules under perspective projection, so a flat rendering cannot stand in for the real
  thing, and measuring a still image has been wrong every time it was tried. Look at it on a device
  before assuming it is right.
- **What it keeps for itself is per device.** The one on your phone and the one on your Mac each have
  their own record — their own self-description, their own cares, their own people. They do not share a
  notebook. This is deliberate rather than pending: one individual does not live in two bodies, and it
  avoids cross-device sync, conflicts and doubled budgets as a class of problem.
- **Nothing verifies that a key is accepted by the server it is sent to.** These packages are checked for
  the right server and the absence of credentials; whether a given CodeFlying key works against
  `baas.kuafuai.net` versus `myapp.codeflying.app` has not been exercised end-to-end.
- **The Mac still falls back silently when no server is configured.** Every package here carries one, so it
  does not arise for these downloads — but a locally built app with an empty domain resolves to the local
  backend and sends whatever key it has to `api.deepseek.com`, while the self-check reports "Configured".
- **`docs/design/inner-drive.zh-CN.md` still opens with "草案，未实现"** although the classes it describes
  are all present. That status line is the author's to change.
- **The wake threshold's margin is thin**, carried from `v0.3.2`: the eight measured judgements sit in
  1.47–2.05 with the line landing in the gap between 1.69 and 1.77 — 0.08 wide.
- **A light generated page still fades in over a dark stage.** Carried from `v0.3.1`; the app's own
  default has been light since `v0.4.1`.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships with a single
  newline, which reads as empty. A key written into it would outrank every build setting.
- Two issues from `v0.1.0` are **unchanged and untouched**: `tools/verify_faces_lab.py` still reports
  7/16 assertions passing, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. On Android the app asks for accessibility,
overlay, notification access, SMS and call log, and it can complete a payment by tapping; on the Mac it
asks for accessibility, screen recording and notifications. The only guardrail on that path is Android's
`FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the model, not enforcement.

**It keeps its own record now, and that record is on your device.** The notebook is encrypted with a
key in the platform keystore; the wiki is plain files by design. Anything you would not want in a plain
file should stay in the notebook side.

## Install from source

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.8.1

# one variant, by hand:
./gradlew :app:assembleDebug -PdefaultLang=en -PcodeflyingDomain=myapp.codeflying.app -PcodeflyingSsl=true

# or all ten files, the way the release was built:
bash ~/.workbuddy/skills/andee-release-ship/scripts/build_variants.sh
```

`-PcodeflyingKey=` and `-PgoogleVoiceKey=` are refused on purpose — a published package carries no
credential.

There is a getting-started guide: **[docs/getting-started.md](../getting-started.md)**, and
**[docs/getting-started.zh-CN.md](../getting-started.zh-CN.md)** in Chinese.

**Upgrading:** `versionCode` moves `18 → 19`, so the Android package installs over v0.8.0 normally. The
Mac app's version string follows the same number. Existing memory, notebook, todos and chat history are
untouched; if you had picked one of the other faces, your choice is unaffected — only the default face
changed. **One thing will appear on its own:** an existing notebook picks up the evening-picture todo on
the next start, the same one a fresh notebook gets. If you don't want it, delete or pause it — it will not
come back.
