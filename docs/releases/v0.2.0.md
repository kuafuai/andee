# v0.2.0

**Three new capabilities and two permission fixes.** A minor bump rather than a patch, because the
three are new capabilities by the definition in [CHANGELOG.md](../../CHANGELOG.md#versioning-policy) —
the first release where that rule has had to decide anything.

The permission pair is the part worth reading. The app had been telling the model things about the
system permission sheet that measuring on a device showed to be false — once in the direction that
made the model act on a grant nobody had given, and once in the direction that hid the question from
the person meant to answer it.

> **No APK is attached to this release, on purpose.** The release build type has no `signingConfig`
> and there is no keystore in this repository, so `assembleRelease` emits
> `app-<abi>-release-unsigned.apk`, which will not install until you sign it. Shipping a binary a
> reader cannot install would be worse than shipping none. Build it yourself — see *Install* below.

## Highlights

- **Long-press a history row to read the log behind it.** The scrollback says what was said; the new
  page shows what earned the right to say it — which tools ran, with what arguments, what came back,
  what the model reasoned, and what each request cost in prompt tokens. It was already on disk and
  reachable only with `run-as`.
- **A single tap on the ball stops what is running and then listens.** Redirecting a busy assistant
  used to take two gestures and four taps; tapping something busy and having it stop and listen is
  what one person does to another.
- **An empty card now offers ready-made scenes** instead of 还没有对话 and nothing under it — one
  bubble per preset, each with a sentence you could have said. Tapping one adopts the scene and then
  speaks it.
- **The system permission sheet can actually be seen now.** It was being drawn *underneath* the
  expanded card, so the dialog was up and focused while the screen showed nothing but the card.
- **`request_permissions` no longer claims success it cannot observe.** It answered
  `{"started": true}` even when Android drew no dialog at all, so the model read "it is on" and
  immediately used the permission.

## What's Changed

### Added

- **Long-press a history row to open its log** (`ui/TracePage.kt`). Joined to the row by
  `<process start>-<gen>` — `gen` alone would have been wrong, because it restarts at 1 with every
  process while the trace file is persistent, so a scrollback matching on it would open a reinstall's
  first turn onto yesterday's first turn. Rows written before this release, hub-brain rows,
  scene-change rows and notification read-outs offer no gesture, because `turn = null` means there is
  no log to open. Two page faults were caught by reading records back off the device rather than by
  reasoning about them: the `turn` card labelled its body "Said" (putting the user's own sentence in
  the assistant's mouth), and the `end` card said "Turn ended" when `BrainTrace.end` is written only
  on an *abnormal* finish.
- **A single tap on the ball stops, then listens.** The stop is `stopEverything()`, reused so the
  single tap and the triple tap cannot drift apart, and guarded on `dispatcher.isTaskActive()` so an
  idle tap does not clear a pending 继续修改 or flash 已停止. Triple-tap is still the immediate stop.
  Verified on device (HONOR AMM-AN00).
- **Ready-made scenes on a card with no history.** Tapping a bubble **adopts** the scene before it
  speaks — a bubble that only sent its sentence asked the model about a scene nobody had saved. It is
  `adoptIfMissing`, so tapping the same bubble again later leaves your own edits intact. The strip is
  `GONE` for good the moment there is a conversation. Verified on device (HONOR AMM-AN00).

### Fixed

- **`request_permissions` reported an attempt as an outcome.** The reply now carries `mode`
  (`solo` / `handoff` / `settings`), `result` (`granted` / `denied` / `no_dialog` / `waiting`) and
  `next`. The split that pays for it: a refusal and a silent block both read `PERMISSION_DENIED` and
  demand opposite responses, and `shouldShowRequestPermissionRationale` — readable only from an
  Activity — is what separates them. Measured before the fix on turn `1791621839492-4`: the request
  returned at +19.257s, `get_location` fired at +20.839s and answered `permission denied` 1 ms later,
  so the model gave the user 1.582s to find a dialog that was never drawn. Verified on device; 37
  unit tests pass.
- **The permission sheet was drawn underneath the expanded card.** Our overlay sits above every
  activity, so `GrantPermissionsActivity` was drawn below the card — the dialog really was
  `ResumedActivity` and `mCurrentFocus` while a screenshot showed nothing but the card. The card now
  folds first, and only when `confirm=true`, because the first call is the script the brain reads back
  and that one belongs in the card.
- **Both READMEs point at the one-click build page**, and the "any app" feature line was reworded in
  both languages — "not a list of integrations" was being read as a claim about integrations this app
  has rather than a claim about aim.

### Changed

- **The prompt's claim about the permission sheet was wrong and is now the measured one.** It said
  the sheet "does not take a tap you inject". With the card folded, an injected tap on 「始终允许」
  really does grant — `READ_CONTACTS` went false → true, and one tap on 「本次使用允许」 produced an
  `ACCESS_FINE_LOCATION` carrying `ONE_TIME`, a flag only that button can set. The earlier four
  failures had one cause and it was our own card eating the touch. The rule becomes **"you cannot read
  it, so do not aim at it"**: the sheet exposes no accessibility elements, so any tap is blind, and
  the button at the bottom of this screen is 「禁止后不再提示」, which nothing can undo.

## Known issues

- **A build with CodeFlying compiled in but no API key can raise the wrong complaint.** The
  self-check's availability test looks at `CODEFLYING_ENABLED` and the domain rather than the key, so
  such a build reports 大脑 key missing and sends the user to fill in a DeepSeek key — while the real
  cause is at build time. Carried over from `v0.1.1`; not fixed by this release.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing against the committed
  `reports/ball-faces-lab.html`, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. This app asks for accessibility, overlay,
notification access, SMS and call log, and it can complete a payment by tapping. The only guardrail on
that path is Android's `FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the
model, not enforcement.

## Install

Android 11+ (`minSdk 30`), arm64-v8a for anything bought in the last several years. There is no binary
in this release; build one:

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.2.0
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

`assembleRelease` needs your own keystore — the repo has none, so it produces an unsigned APK. Either
way the APK is **per-ABI** (`splits` in `app/build.gradle`), so pick the file that matches the device.
Full from-scratch setup is in the README's **Provisioning** section. Then, in this order: grant
Overlay → enable Accessibility → tap the ball → put in your own keys under ⚙.

**Upgrading from v0.1.1:** `versionCode` moves `2 → 3`, so this installs over it normally. History
rows written by an older build carry no `turn` field, so they will not offer the new long-press —
that is by design, not a migration failure.
