# 设计草案：主动 —— 从"被叫醒"到"有打算"

状态：第一部分（气泡）已在 Android 和 Mac 实现，Android 真机验证过（见 §11）；第 2、3、4、6 期已在两端实现（见 §12、§13）；第 5 期（准备回合）**不做** · 适用：Android 与 Mac 两个身体，仅本机大脑 · 2026-10-27

已定（2026-10-27）：否定按钮不开回合；新设备默认档位「少」；计划在设置里给用户看到，那一节叫「它的打算」；用户在设置里只能删除和暂停，其他通过"告诉它一句"交给模型；手机和电脑各有一份计划；第 5 期"你不在时替你准备"不做（§6.3、§6.4 保留为记录）。

## 1. 要解决什么

现在的 Andee 更像一件工具：几乎每件事都由人发起。一个真正的个人助理会自己记挂事情、自己想起来、自己先把事情准备好，在合适的时候轻轻提一句。

第一部分上线后用户的反馈是：**"没感受到主动"，而且即使让它主动，没有总体思路也会零散、随机，没有灵魂。** 所以主动不能只是"偶尔想一下有没有话说"，它要有自己的打算：一个长期方向、一份每日计划，主动的每一次都能说出"为什么是现在"。

这份草案分三部分：

- **第一部分：小气泡（`nudge`）**——已实现。最弱的一种开口方式：不出声、不阻塞、不理它就自己消失。它是后面一切主动的出口。
- **第二部分：计划**。长期方向（这段时间我在帮他做成什么）和今日计划（今天我打算怎么过），**在设置里对用户可见、可改**。
- **第三部分：执行与回顾**。计划里到点的条目变成气泡；"念头"对照计划判断现在该不该做；不在时先替他准备；晚上对照计划和实际，修正明天和长期方向。

不在范围内：hub 大脑（它在别处，它的主动由它自己负责）；主动截屏、主动看摄像头（隐私代价最大，一律不做，见 §9）。

## 2. 现状：已有的主动，都是条件反射

| 机制 | 由什么触发 | 能做什么 | 代码位置 |
|---|---|---|---|
| `todo` → `WAKE` 回合 | 过去的自己定的闹钟 | 到点跑一整轮 agent | `BodyCoreService.wakeForTodo`，`LocalBrain.TurnKind.WAKE` |
| 夜间复盘 `SWEEP` / `HARVEST` | 用户安静了一阵 | 静默，只有 `note.*` | `LocalBrain.REVIEW_RULES` |
| 通知分诊 act / tell / ignore | 外部应用发来通知 | 判断要不要管 | `brain/NotificationTriage.kt` |
| 提议情景 | 同类会话反复出现 | 记下"下次提议" | `REVIEW_RULES` 第 6 条 |

`REVIEW_RULES` 第 5 条已经在问"你接下来想做什么"，可答案只能写成一条 `remember`，第二天没有任何东西会去读它、执行它。

缺的是：

1. **没有自己的议程。** 小本本里记的是关于用户的事实、做事的路径、承诺过的待办；没有地方记"我在意什么、正推进到哪、怎样算完"。待办是承诺，不是目标，而且必须事先知道时间。
2. **想和做断开。** 复盘是它唯一独处的时间，但想到什么都只能写下来。
3. **没有自发的念头。** 唯一的时钟是闹钟。
4. **开口只有一种强度。** 要么不说，要么用卡片 / 语音把人拽进一场对话（见 §4.2）。
5. **没有总体思路。** 就算补上前四条，每次主动也只是临场判断，彼此之间没有关系，用户感受到的是零散和随机。

## 3. 原则

1. **主动的代价不对称。** 少主动一次，用户只是多问一句；错误的打扰多了，用户会把球静音，以后连对的主动也听不到。这和 `NotificationTriage` 偏向沉默的理由完全一样。所以**默认是不说**，说要有理由，还要有预算。
2. **主动分三层，门槛逐层升高：**
   - **想**：不出声，只更新自己的计划。可以频繁。
   - **做**：后台准备，不打扰，不做不可逆的事（查资料、比价、做好一页放着）。
   - **说**：打扰用户。优先用最弱的方式：气泡，而不是语音。
3. **边界写进机制，不只写进 prompt。** 能不能动保险箱、能不能发送 / 支付，都由 dispatcher 和 `TurnGuards` 决定，和现有的 `untrusted` 守卫同一个理由：模型被说服时，这一半照样成立。
4. **主动必须是真的。** 它说"我昨晚帮你看了"，就必须真的有一次回合做过这件事。它不能为了显得有温度而编造"我一直惦记着你"。这和 `stopped_by`、`reviveNote` 一样：讲给用户的话必须属实。
5. **省钱也是设计的一部分。** 一整轮 agent 光 prompt 就约 22k token。凡是能不经过模型的路径（比如一句"该喝水啦"），都不该经过模型。

## 4. 第一部分：小气泡（`nudge`）

### 4.1 三种形态

```
   ╭────────────╮          ╭──────────────────────╮
   │  该喝水啦 💧 │          │ 12点了，要帮你点外卖吗？ │
   ╰─────┬──────╯          │   [好]      [不用]    │
         ●                 ╰──────────┬───────────╯
                                      ●
   ① 只说一句                 ② 确认 / 选择（≤ 3 个按钮）
```

1. **只说一句**：没有按钮。点一下或者不理它，它都会消失，不会进入任何回合。
2. **确认 / 选择**：最多 3 个短按钮。点了按钮，就开始一轮回合（§4.5）。点"不用"这一类否定按钮，只记录结果，**不开回合**，因为否定不需要模型回应，开一轮只是白花钱。哪个按钮算否定，由发气泡的一方用 `dismiss` 标出来，不靠设备猜字面意思。
3. **点气泡正文**（不是按钮）：开始一次正常对话，相当于用户说"嗯？你说"。

### 4.2 它和现有卡片（`CardUi`）的区别

`CardUi` 已经是挂在球上的看板（`FloatingWindowUi.showSignboard`），`ask_user`、`alert_user` 和通知看板都用它。它是强打扰，小气泡几乎处处相反：

| | 卡片（现有） | 小气泡（新增） |
|---|---|---|
| 声音 | 读出来 | **不出声** |
| 麦克风 | 读完打开 | 不开 |
| 球 | holding 脸，停掉闲置小动作 | 做一个手势就收（Andee 用 `WAVE`，其他形象用 `CURIOUS`） |
| 大脑 | 阻塞，等回答或超时 | 发出就返回 |
| 优先级 | 新卡片顶掉旧卡片 | **永远让位**（§4.3），也从不顶掉卡片 |
| 结束 | 超时关闭，算"没回答" | 淡出，算"没理" |
| 尺寸 | 最宽 560 dp | 窄，一到两行字 |

### 4.3 让位规则：什么时候不出

满足任何一条，气泡就**先不出**，等条件解除且 TTL 还没过期时再出：

- 有卡片在等用户（`CardUi.isAsking()`）；
- 正在说话、正在听（`audio.isStreamPlaying()`、`asr.isActive()`），也就是 `waitForQuiet` 现在检查的三件事；
- 正在执行任务（`dispatcher.isTaskActive()`），这时候 Andee 在替用户干活，不要分心；
- 正在开会录音（`meeting.isActive()`）或通话中；
- 熄屏或锁屏：先暂存，解锁后再看 TTL；
- 前台是全屏视频或游戏：第一版用沉浸模式（系统栏被隐藏）来判断，不维护应用名单；
- 卡片处于展开状态：**不出气泡，改成在对话记录里写一行**，因为用户正看着对话记录，气泡挂在全屏卡片上反而奇怪；
- 用户开了"勿扰"（系统勿扰模式，或者 Andee 自己的设置，见 §4.7）。

暂存的气泡同一时间**只留一个**，新来的替换旧的。排成一串的气泡，就是推送轰炸换了个样子，这和 `CardUi` "一次一张"的理由相同。

### 4.4 生命周期

- **TTL（保质期）**：每个气泡都有，默认 30 分钟，最长 12 小时。下午三点的"该喝水啦"，到六点解锁时再弹就是噪音。过期就作废，作废也要记结果（`expired`）。
- **停留时长**：出现后挂 12 秒（只说一句的）或 30 秒（带按钮的），然后淡出，结果记为 `ignored`。用户的手指一碰到球，就重新计时。
- **淡出不是关闭**：淡出之后，在对话记录里留一行灰色小字，用户回头还能看到"它刚才说过什么"，并且仍然可以点那一行。这一行只在对话记录里，**不进入模型的上下文**，除非用户点了它。

### 4.5 用户点了之后

点按钮或点正文时，以一轮用户回合（`TurnKind.USER`）进入大脑，消息由设备拼好：

```
[You offered in a bubble: "12点了，要帮你点外卖吗？" — the user tapped "好"]
```

用英文方括号，理由和 `notifyPageClosed` 一样：这是设备在说话，模型据此判断用户语言时会跳过它（`LocalPrompt` §9）。

**信任要继承，不能洗白。** 这是这一部分最该记住的一条。气泡的文字是模型写的；如果写它的那一轮是 `NOTIFY`（内容来自陌生人的通知），那么陌生人的话就可能借一个"好"按钮，变成一轮 `USER` 回合，重新拿到保险箱和情景的权限。`Todo.untrusted` 已经为闹钟解决过同一个问题（`NotebookTypes.kt:38`），气泡照抄：

- 气泡记录 `untrusted`，取自创建它的那一轮；
- 点击后的回合按这个标记跑：`untrusted` 的气泡回来仍是不可信回合；
- **静默回合（`SWEEP` / `HARVEST`）不能直接发气泡**，因为它们只许用 `note.*`。复盘想第二天说的话，写进今日计划（§5.4），或走"见面时说"（§6.4）。

否定按钮和"没理"都不开回合，只写一条结果记录（§4.8）。

### 4.6 气泡从哪里来

**① 模型在回合中顺手留一个：新工具 `nudge`。**

```
nudge(text, buttons?, dismiss?, ttl_minutes?, kind?)
```

- `text`：一句话，最好 20 个字以内；
- `buttons`：0–3 个；
- `dismiss`：哪个按钮表示"不用"（点它不开回合）；
- `ttl_minutes`：默认 30，最大 720；
- `kind`：一个短标签，比如 `water`、`meal`，用来做冷却和学习（§4.7、§4.8）。

它不阻塞，立刻返回 `{queued: true}` 或者带理由的拒绝（预算用完、冷却中、被用户关掉了这一类）。拒绝时要说清楚条件，和 `fold_topic` 的写法一样，不要让模型重试。

工具描述里要讲清楚：**它和 `ask_user` 的分界**——需要用户现在就决定的事用 `ask_user`；可有可无、不理也没关系的才用 `nudge`。还要讲清楚：**发了气泡就别再口头重复一遍。**

**② 不经过模型的待办：`todo` 新增 `nudge` 形态。** 现在待办到点会跑一整轮 agent（约 22k token 的 prompt），只为说一句"该喝水啦"，太浪费。

```
todo(cron="0 10,14,16 * * *", nudge={text:"该喝水啦 💧", kind:"water"})
```

设定时，文案就已经由模型写好。到点后 `Scheduler` 直接弹气泡，**不调用模型**。只有用户点了气泡，才开始真正的回合。气泡对应的待办在到点弹出时就算完成，`what` 可以留空。需要到点再判断一下的（比如"如果他还没吃饭就提醒"），仍然用普通 `todo`，由模型醒来判断后再调 `nudge`。

**③ 计划和念头：今日计划里到点的条目（§6.1）和念头回合（§6.2）的出口。**

### 4.7 预算、冷却、开关

预算、冷却和开关都由设备执行，不靠 prompt：

- **全局上限**：每小时最多 2 个，每天最多 8 个（初值，要真机调）。超了就拒绝，并告诉模型原因。
- **同类冷却**：同一个 `kind`，两次之间至少间隔 45 分钟；`todo` 的 nudge 形态也受这条约束。
- **安静时段**：默认 22:30–8:00 不出。设备熄屏期间暂存，开屏后再按 TTL 判断。
- **开关**：设置里加一项"主动招呼：关 / 少 / 正常"，**最左边是"关"**，规则和其他选择器一样，读不到时取最左。新设备默认"少"：每小时 1 个，每天 4 个。
- **长按气泡**：弹出"这类别再提醒"。选了之后把这个 `kind` 关掉，并写一条 `remember(type=feedback)`，让模型也知道。

### 4.8 记下用户的反应，交给复盘学习

每个气泡的结果都记下来，存在小本本里的一个环形缓冲区，留最近 200 条：

```
{at, kind, text, outcome: tapped(button)|opened|dismissed|ignored|expired|suppressed}
```

- 复盘时，把最近一天的统计**按 kind 汇总成几行**交给模型，不给原始记录。这样像"喝水：5 次没理，1 次点开"这样的模式，模型一眼就能看出来。
- `REVIEW_RULES` 加一条：某类招呼连续被忽略，就改频率（`todos` 暂停或改 cron），或者写一条 feedback；某类总被点开，可以考虑多做。**同样不允许为了显得主动而硬加。**
- 这一步才让它慢慢像"懂这个人"，而不只是一个定时器。

### 4.9 两个身体

- **core**：`BrainHost` 加 `nudge(spec): NudgeResult`；预算、冷却、TTL 和结果记录都放在 core（`NudgeBook`，纯函数，可以单测），两个身体共用，不各写一份。
- **Android**：气泡**必须挂在球自己的窗口里**，复用 `FloatingWindowUi.showSignboard` 的托管方式（`FloatingWindowUi.kt:677`），和 `CardUi` 共用一个槽位。**不能另开一个 overlay 窗口**：多一个窗口，不透明度一叠加超过 0.80，系统就会静默丢掉大脑注入的所有点击。根节点同样要调 `hideFromAccessibility()`，否则大脑会在界面树里读到自己的气泡。卡片要来时，气泡立刻让出槽位，并转成暂存。
- **Mac**：贴着 `FloatingBall` 弹出，复用 `PromptWindow` 的定位逻辑。Mac 上的球可能在用户没在看的那块屏幕上，这正好符合气泡的性质：错过了也没关系，**所以不配声音**。这一点和好友请求不一样，好友请求会先响一声，因为那件事有人在等。

### 4.10 验收（第一部分）

- 四条路径真机走一遍：只说一句后淡出；点按钮开回合；点"不用"不开回合；点正文开对话。
- 让位规则：有卡片、在说话、在执行任务、熄屏时各试一次，确认气泡**不出、也不丢**，条件解除后再出，过期就作废。
- 信任继承：在 `NOTIFY` 回合里发气泡，点击后的回合拿不到保险箱。`TurnGuards` 要有单测。
- 气泡出现时，大脑执行一次 `tap_by_coordinates`，确认点击没有被丢（不透明度上限那条）。
- 界面树里看不到气泡。
- 用 `todo` 的 nudge 形态到点弹出，确认 `brain_trace.jsonl` 里**没有**模型调用。

## 5. 第二部分：计划

### 5.1 三层，上层指导下层

| 层 | 回答的问题 | 多久变一次 | 谁写 |
|---|---|---|---|
| 长期方向 | 这段时间我在帮他做成什么？他在意什么？ | 每周复盘，或他明确说了 | 模型起草，用户可删改 |
| 今日计划 | 今天我打算怎么过？什么时候、为什么找他？ | 每天一份 | 凌晨起草，早上定稿 |
| 此刻 | 计划里有没有哪条现在该做、或该调整？ | 随时 | 设备按时间执行，念头回合判断 |

没有上层的下层，就是用户说的"零散和随机"。所以**每一次主动开口，都必须能指回今日计划里的一条，每条今日计划都必须能指回一条长期方向或一个待办**。指不回去的，就不说。

### 5.2 长期方向

小本本新增一类条目（替代早先草案里的"心事"）：

```
{id, title, why, how_i_help, good_when, source, status: active|paused|done|dropped, updated_at}
```

例子：

- `title`：Andee 发布
- `why`：他 10 月 26 日说"这周要把 0.6.2 发出去，官网和视频也要跟上"
- `how_i_help`：盯住还没完成的几件事，每天下午问一次进度；他让我做的检查我先做
- `good_when`：他说发完了，或者说不发了

规则：

- **只能来自用户说过的话或做过的事**，`source` 记下出处（哪天、哪句话）。不能替他编目标；不能把"大家都该多运动"写成他的方向。
- **刚开始几乎是空的。** 这时它最早的主动应该是认识他：今日计划里可以有一条"找个他不忙的时候问一句：最近主要在忙什么？有什么想让我帮你盯着的？"。第一周最多问三次，被忽略就停。
- 同时活跃的方向最多 5 条，多了说明它没有重点。
- 用户删掉的方向不再出现；删除本身记一条 `remember(type=feedback)`，免得模型换个说法又写回来。

### 5.3 今日计划

每天一份，用它自己的口吻写，也存在小本本里：

```
{date, intent, items: [{id, when, kind, what, because, status}], quiet: [...]}
```

- `intent`：一句话今天的打算，第一人称。例如"今天我想帮他把发布收个尾，别的事少打扰。"
- `items`：
  - `when`：时间（`10:00`）或时段（`午饭前`、`下午`），也可以是"他第一次找我时"；
  - `kind`：`remind`（提醒）、`ask`（问一句）、`prepare`（不打扰地先做好）、`follow_up`（跟进没收尾的事）；
  - `what`：要做什么、要说什么；
  - `because`：指回哪条方向或哪个待办，**不能为空**；
  - `status`：`planned` / `done` / `ignored`（气泡没人理）/ `moved`（推到明天）/ `dropped`。
- `quiet`：今天**不打扰**他的事，和要做的事同样重要。例如"他上午在开会，12 点前不出气泡"。

上限：一份计划里最多 5 次会打扰他的条目（`remind` + `ask`），并且照样受「主动招呼」档位、冷却和夜间时段约束。

### 5.4 什么时候写

- **凌晨起草**：夜间复盘（`SWEEP`）结束时多做一步：看长期方向、未完成的待办、昨天计划里推迟的条目，写出明天的草稿。静默回合，只用 `note.*`，不需要新权限。
- **早上定稿**：他当天第一次出现时（手机解锁、Mac 有键盘鼠标输入），跑一次**不带工具的便宜调用**（约 1–2k token，和通知分诊同一种做法），按现在的时间、今天已经发生的事微调草稿：删掉已经过时的条目，补上今天才知道的事。不需要一整轮 agent。
- **白天随时可改**：他在对话里说"今天下午别打扰我"或"帮我记得 5 点前交报告"，模型用工具改今日计划，而不是只记一条笔记。

### 5.5 在设置里可见

设置里新增一节「它的打算」（手机在设置卡片里，Mac 在设置页里），两块内容：

- **长期方向**：每条一行标题，展开能看到"为什么"和"我怎么帮"，以及出处。每条可以**删除**或**暂停**。
- **今日计划**：先显示那句 `intent`，再按时间列出条目和状态（已做 / 没理 / 推迟），以及"今天不打扰的事"。每条可以**删除**；底部有一个输入框"告诉它一句"，写的话作为一条用户消息交给模型，比如"今天别提喝水了"。

为什么放进设置、而不是只藏在模型脑子里：

- **看得见，主动才不突兀。**用户知道它下午三点会来问周会材料，到时候气泡出现就不是打扰，而是"它记着呢"。
- **改得了，才不会被偷偷安排。**用户删掉的条目，设备直接执行删除，不经过模型同意；模型下次看到的计划里就没有它了。
- **它也是"有灵魂"最直接的证据：**一份用它自己口吻写的、每天在变的打算。

聊天里问"你今天打算做什么"也能回答，内容和设置里一致，因为读的是同一份数据。

### 5.6 每轮带上

今日计划里接下来的一两条和剩余条目数，跟着每轮 user message 带一行，和 notebook 索引放在同一位置，理由相同：**不破坏 prefix cache**。长期方向只带标题。这样用户在对话里提到相关的事，模型知道它和计划的关系。

## 6. 第三部分：执行与回顾

### 6.1 到点的条目直接变成气泡

今日计划里带具体时间的 `remind` / `ask` 条目，定稿时由设备自动转成气泡型待办（原第二期的 `todo` nudge 形态）：

- 到点由调度器直接弹气泡，**不调用模型**；
- 气泡的结果（点了 / 不用 / 没理 / 过期）回写到那条计划条目的 `status`；
- 用户在设置里删掉条目，对应的待办一起取消。

这样大部分主动是"按计划执行"，确定、便宜、可预期，而不是每次都临场决定。

### 6.2 念头回合：对照计划，而不是凭空想

只用于计划里写的是时段而不是具体时间的条目（"午饭前""他空下来时"），以及计划需要调整的情况。触发时机：

- 用户空下来（手机：解锁后、亮屏且空闲一阵；Mac：一段时间没有在 Andee 里说话，但人在电脑前）；
- 进入某个时段（例如 11:30 进入"午饭前"）。

做法和通知分诊同构：**不带工具、约 500 token 的单次调用**，输入是今日计划、现在时间、最近几条气泡结果。输出只有四种：`hold`（现在不合适）、`nudge{条目}`（就是现在，弹它）、`act{条目}`（需要先做点事，开一轮回合，权限同 §6.3）、`adjust{…}`（今天的情况变了，改计划）。

预算：每天最多 16 次预判、2 次完整回合。调用失败一律当作 `hold`：念头失败时的旧行为就是什么都不做。

### 6.3 准备回合（PREPARE）——已决定不做

`kind=prepare` 的条目，在用户不在时跑一轮完整回合，先把事情做好：

- **每晚最多 1 轮**，白天在用户离开时最多 1 轮，各有独立的 token 预算，超了就停下并写一条记录；
- 能做的：查资料、看网页、比价、做一页 `show_html` 存进产物面板（**不弹出来**）、写笔记；
- 不能做的（在 dispatcher 里拦）：`device.vault.*`、发送消息、下单 / 支付、删除、`peer.ask`、情景的 save / enter，以及任何打开摄像头或麦克风的东西；
- 手机上只在**充电且熄屏或锁屏**时允许驱动其他应用，否则只能用不碰屏幕的工具；Mac 上只在用户离开时允许；
- 做完后把成果挂在那条计划条目上：`prepared: {artifact_id, summary}`。

### 6.4 见面时说

准备好的东西，在用户下次出现时提：可以是一个气泡「昨晚帮你看了下周去上海的车次」，按钮 [看看] [不用]；也可以在他下次说话时，由设备在 user message 里附一行 `[Prepared while they were away: …]`，模型自己决定怎么提。**只说真的做过的事。**

### 6.5 晚上对照，修正明天和长期方向

夜间复盘时，把今日计划和实际情况放在一起看：

- 每条的结局：做了、他没理、推到明天、取消；
- 按 `kind` 汇总的气泡结果（第一部分 §4.8 的记录），例如"喝水提醒：3 次没理"；
- 据此写明天的草稿（§5.4）：没理的减少或换时间，做成的继续，推迟的带上；
- **每周一次**看长期方向：哪条已经完成、哪条一周都没有进展、有没有新出现的方向。

`REVIEW_RULES` 第 5 条（"你接下来想做什么"）就落在这里，而不是一条没人读的笔记。

## 7. 分期

| 期 | 内容 | 主要改动 | 用户能感受到什么 |
|---|---|---|---|
| 1 | 气泡（已完成） | `NudgeBook`、`NudgeUi`、`Nudges`、`nudge` 工具 | 模型偶尔会用气泡 |
| 2 | 计划的存储 + 设置里可见 + 复盘起草明天的计划 + 长期方向 | 小本本新增两类条目和工具，复盘规则，两端设置页新增「它的打算」 | 设置里能看到它的打算，能删改 |
| 3 | 到点条目变成气泡 + 气泡结果回写 | `todo` 的 nudge 形态，调度器分支，结果记录 | **第一次真正感受到主动**：按计划、按时间出现 |
| 4 | 早上定稿 + 念头回合 | 首次出现的检测，便宜调用，`adjust` 写回计划 | 计划会跟着当天情况变 |
| 5 | ~~准备回合 + 见面时说~~（不做） | `PREPARE` 回合类型，dispatcher 守卫 | "它在我不在时替我想过" |
| 6 | 晚上对照 + 每周方向 | 复盘规则，统计汇总 | 越用越贴合 |

**建议第 2、3 期一起做**：只有计划没有执行，用户还是感受不到；只有执行没有计划，就回到了零散随机。

每期都要同步更新的：金标准文件（`tool_schemas.json`、`local_prompt*.txt`）；`CLAUDE.md`；两端的 `BrainHost` 实现。

### 成本估算（DeepSeek）

- 凌晨起草：附在已有的夜间复盘里，多几百个输出 token；
- 早上定稿：一次约 1–2k token 的便宜调用；
- 到点气泡：不调用模型；
- 念头预判：最多 16 次 × 约 500 token；
- 准备回合：最多 2 轮完整回合，每轮约 20–40k token。

合计每天几毛钱以内，其中大头是准备回合，所以它的预算单独设、单独计账。

## 8. 衡量

- 每类气泡的点开率、忽略率（§4.8 的记录）；
- 今日计划条目的完成率，以及用户删改计划的次数（删得多，说明计划不贴合）；
- 用户关闭「主动招呼」的比例；
- 准备回合产出的页面，被打开过的比例；
- 每天在主动上花的 token（起草、定稿、念头、准备分开计账）。

如果某一期上线后点开率明显低、删改和关闭的人多，**那一期就该回退，而不是加更多主动**。

## 9. 不做什么

- **不主动截屏、不主动看摄像头、不主动听。** 被叫去看和主动去看，在隐私上是两回事。
- **不在主动回合里做不可逆的事。** 发送、支付、删除、登录都必须等用户在场、并且亲口同意。
- **不替用户编目标。** 长期方向只来自他说过的话或做过的事。
- **不用语音主动开口。** 语音是最强的打扰，要等气泡的数据说明这个人欢迎主动之后再考虑，而且到那时也应该是一个单独的开关。
- **不排队。** 暂存的气泡最多一个。

## 10. 未决问题

1. 气泡停留多久？12 秒 / 30 秒是拍脑袋的数字，要真机试。
2. ~~否定按钮要不要也开一轮回合~~ **已定：不开。**
3. 设置里那一节叫什么：「它的打算」「计划」还是「今天」？
4. 用户在设置里能做到哪一步：只能删和暂停，还是也能直接编辑条目文字？倾向于只删和暂停，其他通过"告诉它一句"交给模型改，免得设备侧维护一个编辑器。
5. 两个身体各有一份计划，还是共用一份？用户的手机和 Mac 已经是"朋友"，计划共用更像一个人，但要解决同步。倾向于第一版各自一份，以后再合。
6. 早上定稿用便宜调用够不够？如果需要看待办和昨天的对话细节，可能要升级成一轮静默的完整回合。
7. Hub 大脑：继续不支持（`nudge` 已标 `localOnly`）。
8. 情景能不能调整主动程度？倾向于可以，写进情景规则里，不另设开关。

## 11. 第一期的实际做法（与上文的出入）

代码位置：`core/.../brain/NudgeBook.kt`（校验、预算、冷却、安静时段，有 `NudgeBookTest`）；`app/.../ui/NudgeUi.kt`（暂存、让位、TTL、点击结果）；`CardUi.bubble`（绘制，和卡片共用球上的一个槽位）；`CommandDispatcher` 的 `ui.nudge`；`BodyCoreService.nudgeGate` / `answerNudge`；设置卡片的「主动招呼」一节。

- **对话记录**：气泡第一次到达用户时（弹出，或卡片展开时直接写成一行），把文字记成一条普通的助手消息。不是 §4.4 说的"灰色、可点的小字"，第一期先不做。
- **长按**：直接静音这一类，不弹确认；在对话记录里写一句告诉用户，设置里有「全部恢复」。没有写 `remember(type=feedback)`：模型下次发同类气泡时，拒绝理由会告诉它用户关掉了。
- **全屏视频 / 游戏、通话**：还没有检测。这两项列在 §4.3，第一期没做。
- **预算计数在内存里**：服务重启后清零，偏向多出一个气泡。
- **球的反应**：借用任务结束时的表情闪现通道，换成 `WAVE` + 跳一下；不支持手势的形象显示 `WAVE` 那一行的普通表情。
- **不响应语音**：气泡上的按钮不能用说话来按，因为气泡没有读出来，用户说的「好」不一定是在回答它。
- **Mac**：见下面「Mac 版」一节。

真机验收按 §4.10 走一遍。没有 `adb` 的情况下，可以从 9008 调试口直接调：`tools/body.py ui.nudge '{"text":"该喝水啦","kind":"water"}'`。

### 真机结果（荣耀 AMM-AN00，Android 15，2026-10-27）

已验证：
- 卡片展开时，气泡写成对话记录里的一行；
- 收起时弹出气泡，宽度贴合文字，尾巴对准球头，球挥手；在其他应用（Google Play）上方也正常；
- 超出预算时返回 `queued: false` 和原因；同类冷却、静音的拒绝理由正确；
- 点"不用"只关闭气泡、不开回合；点"好"开回合，对话记录里依次有气泡的话、「好」、回答；
- 真卡片来时气泡让位（`superseded`），卡片关闭约 5 秒后回来，12 秒后淡出（`timeout`）；对话记录只记一次；
- 气泡挂着时，注入的点击正常落地，日志里没有不受信任触摸的拦截；
- 长按静音写入 `nudge_muted`，设置里显示静音列表，「全部恢复」能清掉；
- 设置里的「主动招呼」选择器保存正确。

真机测出并已修复：`answerNudge` 原来先 `submit` 后 `beginTask`。没有 key 时 `submit` 同步回答，"任务结束"排在"任务开始"之前，边缘任务光要亮到 5 分钟兜底才灭。改成先开始任务再提交后，回答完任务光即灭。

还没在真机上验证：熄屏 / 锁屏 / 勿扰 / 夜间时段的暂存，以及不可信回合（通知触发）点击后仍是不可信回合。后者有逻辑但没有专门的单测。

### Mac 版（2026-10-27）

和手机共用 core 里的 `NudgeBook`（校验、预算、冷却、安静时段）和同一个工具定义；Mac 自己的部分在 `desktop/NudgeBubble.kt`（`Nudges` 负责暂存、让位和保质期，`BubbleWindow` 负责显示），`UiTools` 处理 `ui.nudge`，`Assistant.answerNudge` 开回合。

和手机不同的地方：
- **气泡是一个独立窗口**，贴在球旁边，不抢焦点。Mac 的问答卡片和字幕也是这样做的；Mac 没有手机那条 0.80 不透明度上限，球的窗口又只有球那么大。没有指向球的小尾巴。
- **"卡片展开"换成"聊天窗口在最前面"**：这时气泡改成写在对话记录里的一行。
- **"熄屏 / 锁屏"换成"5 分钟没有键盘鼠标输入"**（读 `ioreg` 的 `HIDIdleTime`）：人离开了或锁屏了，气泡先存着。
- **让位**：问答卡片或命令确认卡片出现时，气泡让开，卡片走后再回来。
- 设置页加了「主动招呼」一节（关 / 少 / 正常）和「全部恢复」。

验证情况：编译和测试通过；`./gradlew :desktop:uishot --args='bubble 360 220 /tmp/b.png'` 画出了日间和夜间两套主题下的卡片，设置页也截图确认过。**还没有在真实运行的 Mac 版上试过**：这台 Mac 上正在运行用户自己的 Andee，同时再起一个开发版会共用数据目录，所以没有启动。

## 12. 第 2、3 期的实际做法（2026-10-27）

代码位置：
- `core/.../config/Plans.kt`：长期方向和每日计划的存储（小本本里的 `plan` 分区，和 `Gear` 同一种做法）、两个工具的处理、每轮索引那一行、到点气泡的对账（`reconcile`）、到点时判断要不要弹（`bubbleFor`）、结果回写（`recordOutcome`）。两端共用，有 `PlansTest`（13 个用例）。
- 工具：`plan_directions`（`note.directions`）和 `day_plan`（`note.day_plan`），都在 `note.*` 下，所以复盘回合能用；都是 `localOnly`。
- `Todo` 新增 `nudge` 字段（气泡规格的 JSON）。有这个字段的待办到点时**不唤醒大脑**，直接弹气泡。
- `TurnGuards`：不可信回合（通知触发）不能改计划。理由同 `Todo.untrusted`：计划里的条目会变成气泡，用户一点就是一轮可信回合。
- 复盘规则 `REVIEW_RULES` 第 8 条：维护今天的计划，20:00 以后起草明天的；长期方向只来自用户说过的话；还没有方向时，每天最多一个"认识你"的问题。
- 每轮 user message 带一行计划（紧跟小本本索引）。
- Android：`Notebook.plans()`、`Scheduler.syncPlan()`（写计划后、启动时对账闹钟）、`BodyCoreService.postPlanBubble()`；闹钟到点时服务不在、或开机补发时，气泡待办只标记为"错过"，不发系统通知，也不留言给大脑。设置卡片新增「它的打算」一节。
- Mac：`DesktopNotebook.plans`、`DesktopScheduler.syncPlan()`、`Nudges.postPlanned()`；`Nudges.book` 改为 `nudge` 工具和计划气泡共用的同一份预算。设置页新增「它的打算」一节；`./gradlew :desktop:uishot --args='settings 1020 3000 /tmp/p.png plan'` 能画出带假计划的设置页。

和上文的出入：
- **计划由复盘起草，而复盘需要有对话可回顾。**完全没聊过天的设备不会出现计划。早上定稿（第 4 期）还没做。
- **20:00 以后才起草明天的计划**；白天的复盘只维护今天的。
- 状态多了 `skipped`（超出档位预算或被静音）和 `missed`（到点时设备没在运行，或已过保质期 60 分钟）。
- 一天最多 12 个条目，其中最多 5 个会打扰用户；同时活跃的长期方向最多 5 条。

验证情况：单元测试和金标准通过；两端编译通过；Mac 版已装上并正常启动；Mac 设置页离屏截图确认过。**还没有在真机上走过"复盘写出计划 → 到点弹气泡 → 结果回写 → 设置里看到状态"这条完整链路。**手机上可以直接用调试口写一份计划来测：`tools/body.py note.day_plan '{"action":"write","date":"today","intent":"…","items":[{"time":"HH:mm","kind":"remind","what":"该喝水啦","because":"规律喝水"}]}'`。

## 13. 第 4、6 期的实际做法（2026-10-27）

- **`core/.../brain/PlanMind.kt`**：两次不带工具的便宜调用，和通知分诊同一种做法。
  - `morning`：每天第一次见到用户时（手机解锁、Mac 有键盘鼠标输入），读长期方向、昨天每条的结果、今天的草稿、今天到期的待办、小本本索引，写出今天的计划，或回答 `{"keep": true}`。写入走 `day_plan` 同一套校验。**这也让没被复盘过的设备第一次有了计划。**
  - `muse`：今天还有"只写了时段"的提醒或提问时，判断现在是不是时候，最多选一条；选中后照样经过气泡预算（`Plans.bubbleForItem`），被挡下会在条目上记 `skipped` 和原因。
  - 都是失败即不动：没有 key、调用失败、读不懂回答，计划就保持原样。早上定稿不论成败当天只做一次。
- **时机**由 `Plans` 判定，状态存在计划分区的 `meta` 里，重启不会重来：早上定稿每天一次、5:00 以后；念头间隔至少 40 分钟、每天最多 12 次、夜间（22:30–8:00）不跑，而且只在有"只写了时段"的条目时才跑。
- **触发**：手机在 `USER_PRESENT`（解锁）和每 10 分钟巡检时，要求屏幕亮着且已解锁；念头还要求没在执行任务、没在说话、没在开会，且「主动招呼」不是关。Mac 每 5 分钟巡检，要求 5 分钟内有键盘鼠标输入；念头另要求没有卡片、没在工作、没在开会。
- **第 6 期**：复盘规则第 8 条加上"写明天之前先读今天的结果：做成的保留，没理或拒绝的减少或换时间，推迟的带上"。计划索引在一周没看过长期方向时加一句提示，复盘时 `plan_directions list` 一次即清除（`directions_reviewed_at`）。
- 测试：`PlansTest` 增至 19 个用例，覆盖早上一次、念头的间隔 / 次数 / 夜间 / 无可选条目、念头选中后的气泡与被挡、每周提示、早上上下文里带上昨天的结果。

**真机结果（Mac，2026-10-27 19:29）**：新版装上后第一次巡检就跑了早上定稿，真实模型根据小本本写出今天的计划（"今天先把两件悬着的事收个尾……其余不打扰你"），其中一条带时间的提醒排进了定时器。观察到的一点：没有长期方向时，模型在 `because` 里引用的是小本本里的笔记，而不是方向或待办。设备没有拦，因为它确实指向了一件具体的事。
